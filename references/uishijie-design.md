# UI 世界 uishijie.com/ui 设计蒸馏

单站实测（2026-10-25，Edge + playwright-core，1440×900 与 390×844 两个视口）。
采样地址 `http://www.uishijie.com/ui/`（作品聚合页，"UI设计作品欣赏 - UI世界"），324 个元素，浅色，`lang="zh"`。

> 语料里的**第一个内容/资源聚合站**。前两个单站样本（wegic、即时设计）都是营销/产品站，
> 用的是「大留白 + 大字 + 每块一个主张」的节奏；这一份是反过来的极端：**密度优先、卡片不画框、字号只有四档**。
> 它不代表优秀，但**图墙/资源列表这类页面该长什么样，它给了一个可测量的下限和一个上限**。

---

## 一、气质

**一句话：一张贴满缩略图的墙，卡片没有壳。**

可辨识的四个特征：

1. **零 gutter 的 5 列图墙**：列宽固定 300px，卡片自己带 12px 内边距充当间距，
   所以视觉间距 24px 但网格 `gap` 是 0，一屏能放 15 张缩略图。
2. **卡片不画框**：无背景、无边框、无圆角、无阴影（实测 `background: transparent` / `border: none` / `box-shadow: none`），
   分组完全靠缩略图自己的边界。
3. **字号只有四档**：12 / 14 / 16 / 18（18 只给搜索图标），标题 14/700、副行 12/400。
   信息层级靠**字重和颜色**拉开，不靠字号阶梯。
4. **头部一条渐变**：80px 高、`linear-gradient(to right, #0d6efd, #9258f1)`、白字白 logo，
   没有下划线、没有胶囊、没有 hover 动效。

## 二、令牌

```
/* 面 */
--bg:            #ffffff          页面底色，全站唯一
--head-grad:     linear-gradient(to right, #0d6efd 0, #9258f1 100%)   头部 80px
--edge:          #e5e5e5          分页与输入框的 1px 边

/* 文字 */
--ink:           #000000          标题容器
--ink-title:     #333333          卡片标题 14/700
--ink-meta:      #7f7f7f          副行 12/400（分类·时间）
--ink-nav:       #5a5a5a          分类 tab 未选中
--ink-on-dark:   #ffffff          头部导航 14/400

/* 强调（只有两个） */
--brand:         #0d6efd          分类 tab 选中 / 分页当前页 / 链接（Bootstrap 蓝）
--stat:          #ff3300          人气、推荐数字
--stat-hover:    #f13608          鼠标悬停时数字变色（全站唯一 hover 反馈）

/* 圆角与阴影 */
--r-input:       5px
--r-input-btn:   0 20px 20px 0    搜索按钮只圆右侧
阴影：1 处（卡片），其余 0 处
```

要点：

- **全站只有一种底色**。没有 section 换色、没有深色区，节奏靠图与图之间的密度变化，不靠色块分区。
- **强调色是两个，不是一个**：Bootstrap 蓝负责「可点」，橙红负责「数值」。分工清楚，所以没有第三个颜色。
- **阴影几乎为零**。图墙里加阴影会让 25 张图变成 25 个浮起的方块，视觉噪声翻倍——这是它做对的地方。

## 三、字阶与字体

| 用途 | 字号/字重 | 行高 | 颜色 |
|---|---|---|---|
| 分类 tab（选中） | 16/500 | — | `#0d6efd` |
| 分类 tab（未选） | 16/500 | — | `#5a5a5a` |
| 头部导航 | 14/400 | — | `#ffffff` |
| 卡片标题 | **14/700** | 30px | `#333333` |
| 卡片副行 | **12/400** | 24px | `#7f7f7f` |
| 人气/推荐 | 12/400 | 24px | `#ff3300` |
| 搜索图标 | 18/400 | | `#5a5a5a` |
| 页脚 | 14/400 | | `#000000` |

- **四档字号走完全站**（12/14/16/18）。对比 shadcn 后台的 8 档、Wegic 的 10 档：
  内容站不需要字阶阶梯，需要的是**同一档字号里的字重差**（700 标题 vs 400 副行）。
- 字体：`微软雅黑, tahoma, arial, 宋体`，**零 `@font-face`**。
  这是「中文内容站」的合理取舍：用户生成内容页、量级几万张图，自托管中文字体成本不划算。
- 标题行高 30px 比字号大 2.1 倍——给两行截断留空间；副行 24px 与 12px 成 2 倍，行与行之间不用 margin。

**这里有个真问题**：`#7f7f7f` 配 `#fff` 对比度 **3.9:1**，12px 正文低于 WCAG AA 的 4.5:1。
`--ink-nav: #5a5a5a` 是 6.7:1 合格——同一个站里两种灰，一种合格一种不合格，说明是随手取的色。
**结论：12–13px 的次级文字，最浅只能到 `#6b6b6b`（4.9:1）。**

## 四、版式节奏

| 区块 | 高度 | 实测 |
|---|---|---|
| 头部 | **80** | 渐变条，logo `<img>` 300×80 直接铺满左侧，导航项 78×80、搜索组 145+40 |
| 分类条 | **85** | 8 个文字 tab（`li` 61 高，`padding: 0 20px`），右侧「共 11424 个作品」 |
| 图墙 | 1590 | `ul.uibox`，5 列 × 5 行 = **25 张**，列宽 300、行高 318 |
| 分页 | ~90 | Bootstrap 5 `ul.pagination` + `.page-link`，9 个可见项 + « »，共 **476 页** |
| 页脚 | 68 | 友情链接 + 备案号 + 版权声明，无底色 |

三条值得学的：

1. **容器宽 = 1500px 且不居中约束**。5×300 正好铺满 1500，比 1440 视口还宽 60px（见六节缺陷）。
   它选了「列宽整数 + 列数整数」，牺牲了响应式。
2. **每个区块只有一件事**：头部=品牌与搜索，分类条=筛选，图墙=内容，分页=翻页。
   没有「为什么选我们」「三步开始」这类营销块——内容站的节奏是**竖向信息流，不是叙事**。
3. **15 张首屏**。1440×900 下首屏能看到 3 行 × 5 列的前 2.5 行：20 张缩略图。
   这是刻意的：让用户相信「这里很多」。对比营销站首屏只有 1 个大标题。

## 五、组件配方

### 卡片（关键就这一个）

```
li      300×318    padding: 12px 12px 0   无背景/边框/圆角/阴影
  img   275×190    aspect-ratio ≈ 1.447    object-fit: cover
  .tit  275×30     14/700 lh30 #333        单行，超长省略
  .des  275×72     12/400 lh24 #7f7f7f     两行：分类 · 发布时间
  .stat 12px       #ff3300                 人气 784 / 推荐 1
```

- **缩略图比例强制统一**：275×190。来源图片五花八门（后台截图、手机长图、网页全屏），
  不强制比例墙就参差。用 `aspect-ratio` + `object-fit: cover`，不要 `height: auto`。
- **不画卡片壳**：图 + 标题 + 副行三段直接排。25 个壳 = 25 层阴影 + 25 个圆角，噪声翻倍。
- **数据和文案同色不同字**：人气/推荐数字用橙红小一号，是唯一「可点暗示」。
- 标题只给一行（`lh30`、`nowrap` + ellipsis）。两行会让 318px 的行高变成 348，整墙错位。

### 分类条

```
ul > li.selected   padding: 0 20px   高 61
  a                16/500  选中 #0d6efd / 未选 #5a5a5a
右侧计数            14/400  #7f7f7f
```

- **纯文字 tab**：不做胶囊、不做下划线、不做底框。8 个以上分类时这是最省噪声的做法
  （胶囊在 8 个以上会变成一排药丸，视觉重量超过内容本身）。
- 选中态**只换颜色**，不换字重——所以 hover 时不会跳。
- 右侧放总量数字，给规模感。

### 搜索组

```
容器 185×40   input 145×40 白底 #5a5a5a 14px
按钮 40×40    radius: 0 20px 20px 0   图标 18px
```

- 输入框与按钮**拼成一个胶囊**（左方右圆），圆角只在右侧——这种做法在中文站很常见，
  比「两个分开的圆角矩形」省 8px 且更像一个整体。
- 缺陷：该按钮 `x=1460` 超出 1440 视口 20px，页面被它撑出横向滚动（见六节 2）。

### 分页

Bootstrap 5 原生：`ul.pagination > li.page-item > .page-link`，
当前页 `li.active`（蓝底白字）、首尾 `«»` 在 `.disabled` 时置灰、中间用 `…` 省略。
9 个可见项（1–7 … 475 476），共 476 页。

## 六、它自己没做好的七处

1. **移动端零适配（最严重）**：`meta viewport` 有，但布局是固定 1500px。
   390×844 下 `document.scrollWidth = 1500`，每张卡只剩 **64px 宽**，一屏 5 列缩略图全部看不清。
   修正方向见 `css-recipes.md` §14：`repeat(auto-fill, minmax(160px, 1fr))` + `≤640px` 两列。
2. **固定容器溢出视口**：`ul.uibox` 宽 1500，搜索按钮 `x=1460`，在 1440 视口下页面横向滚 60px。
   5 列 × 300 是硬编码，列数改不了。
3. **没有 `<h1>`，`<h2>` 用来装导航**：实测唯一的 `<h2>` 文本是
   「共11424个作品 + 所有作品 + 控件 + 后台界面 + …」——标题标签变成了装饰，读屏会一口气念完 8 个分类。
   内容站至少要有 `<h1>`=页面名、每个卡片标题用 `<h3>` 或纯文本。
4. **卡片 hover 只有小字变色**：缩略图没有任何反馈（无放大、无遮罩、无边框）。
   25 张图里，用户无法预判点哪里能进去——图本身应该是最强的可点区域。
5. **float 布局 + `fn-clear` 清浮动**：老写法，列宽写死在 CSS 里（300px），
   改列数要动 CSS；`display: grid` + `repeat()` 一行就够。
6. **表单无障碍缺失**：搜索按钮无 `aria-label`（内容为空），输入框无 `<label>`，
   27 张图里 2 张无 `alt`。
7. **广告浮层压卡片**：移动端截图里有一张带倒计时的角标图压在第二行卡片上，无关闭按钮。
   这与促销条同类问题——**广告位一旦自成一套视觉，就说明主语言没兜住**。

## 七、能搬什么 / 不能搬什么

| 招式 | 能搬 | 不能搬 / 注意 |
|---|---|---|
| 零 gutter + 卡片内边距当间距 | ✅ 图墙、资源列表、模板库 | 后台表格、表单不要用，密度太高压迫 |
| 卡片不画框（图+标题+副行） | ✅ 以图为主的内容列表 | 文字型列表（无图）必须靠边框/分隔线分组 |
| 缩略图强制同比例 + `object-fit: cover` | ✅ 任何用户上传内容 | 设计稿预览类要 `contain`（不能裁掉画布边缘） |
| 四档字号（12/14/16/18） | ✅ 内容站、社区、资源库 | 管理端至少 6 档（标题/小节/正文/表格/辅助/微标） |
| 文字 tab 做 8+ 分类筛选 | ✅ 分类多的列表页 | 分类 ≤5 个时用胶囊更省空间 |
| 输入框 + 按钮拼胶囊 | ✅ 站内搜索 | 密码框、金额框别拼（误触） |
| 右侧「共 N 个」给规模感 | ✅ 资源站、后台列表 | 数字要真实，虚标会被用户在分页处发现 |

**混合口径**：把这份的「图墙 + 文字 tab」与 shadcn 的后台令牌拼在一个产品里是可以的——
`--font-body: 14px`、`--card-no-shell: true`（图列表区）、`--gutter: 0`（图墙区），
但后台表单区必须切回 `--card-shell: true` + 24px gutter。**同一个产品里允许两套密度，不允许两套圆角。**

## 八、复现清单（照这个顺序做）

1. **先定列宽与列数**，不是 gap：`grid-template-columns: repeat(5, 300px)` + 卡片 `padding: 12px`。
   要响应式就换成 `repeat(auto-fill, minmax(220px, 1fr))`，别锁死 5 列。
2. **缩略图定 `aspect-ratio`**（内容图 1.45 左右，手机截图 0.46，网页全屏 1.6）。
   同一列表里只许一种比例。
3. **卡片不画壳**：`background: none; border: 0; box-shadow: none;`，靠图边界分组。
4. **标题一行、副行两行**，字号 14/700 与 12/400，行高 30/24，副行色 ≥`#6b6b6b`（别再降到 `#7f7f7f`）。
5. **分类条用文字 tab**，选中只换色（16/500），右侧放总量。
6. **分页给可见页数 + 总数**，当前页蓝底白字，首尾箭头 disabled 置灰。
7. **移动端 ≤640px 两列**、`auto-fill` 重排，图墙永远不横向滚动。
8. **hover 反馈给图**：`transform: scale(1.02)` 或 `outline: 2px solid var(--brand)`，别只给小字。
9. **`<h1>` 是页面名**（如「UI 作品欣赏」），卡片标题用 `<h3>` 或 `aria-labelledby` 指向链接。
10. 跑 `scripts/audit.mjs`：重点看 `color-contrast`（12px 灰最容易挂）、`image-alt`、`heading-order`。

## 九、与其他参考文件的关系

- `references/design-evidence.md` — 这份是 A 组第 **12** 个样本，也是语料里**唯一的内容/聚合站**；
  跨站统计因此第一次有了「图墙密度」口径（见该文件二节）。
- `references/page-patterns.md` §2.3「内容站」骨架的最小要素表，可以从这份的版式节奏反推尺寸。
- `references/css-recipes.md` §14「零 gutter 图墙」给了可直接粘的 `.thumb-grid / .thumb / .filter-row / .pager`。
- `references/component-spec.md` 的表格与列表规格是**后台口径**（24px gutter、卡片有壳）；
  图墙是例外，两者不要互相套。
- 与 `references/jsdesign-design.md` 的关系：那份是「浅色 + 彩卡 + 大阴影」，这份是「白底 + 无壳 + 零阴影」。
  同一个产品里混用，就是「内容区无壳、功能区有壳」，边界要用一条分隔线或底色差交代清楚。

## 十、怎么重采

```bash
node <skill>/scripts/probe-ref.mjs \
  --url http://www.uishijie.com/ui/ \
  --out .design/ref --name uishijie --wait 4000

node <skill>/scripts/screenshot.mjs \
  --url http://www.uishijie.com/ui/ \
  --out .design/ref --name uishijie
```

注意三件事：

1. **`probe-ref.mjs` 只抓到 1 个"卡片"**（它按 `.card`/`article` 匹配，这站用的是 `ul.uibox > li`）。
   卡片尺寸必须另写探针：找「同尺寸兄弟最多的父容器」，代码见本文四节数据来源。
2. **页面是 `float` 布局**，`getBoundingClientRect` 的 `y` 值在滚动后会变，量之前先 `scrollTo(0,0)`。
3. **移动端截图看起来和桌面一样**不是 bug：它真的没有响应式，`docW` 永远是 1500。
   判断一个站有没有适配，看 `document.documentElement.scrollWidth` 是否等于 `window.innerWidth`。
