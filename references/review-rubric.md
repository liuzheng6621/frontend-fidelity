# 交付前验收清单

逐项勾，勾不了的在交付说明里写原因。**「脚本绿了」只是其中第三节，不是全部。**

## 一、结构（看图能立刻发现）

- [ ] 三个视口（1440 / 768 / 390）都没有横向滚动
- [ ] 页面有明确的视觉层级：标题 > 主内容 > 辅助信息，不靠字号堆叠也能看出主次
- [ ] 留白成体系：相邻 8px、分组 24–32px，没有「随手 13px」
- [ ] 字号只用了字阶里的值，没出现 15px / 17px / 21px
- [ ] 圆角成套（容器 / 卡片 / 控件 / 标签四档），没有同一层里 6 和 12 混用
- [ ] **所有尺寸是整数**（不许 22.2857 / 30.797 / 44.564 这类 em 缩放的产物），圆角能看出内外递进
- [ ] **阴影两套分职**：普通卡片用「负扩散 + 发丝环」，戏剧性大阴影只给浮起来的设备截图，不混用第三套
- [ ] **图墙/内容列表**：缩略图 `aspect-ratio` 统一 + `object-fit`；卡片不套壳（无背景/边框/阴影）；
      hover 反馈给图本身而不是只给副行小字
- [ ] **图墙用等宽网格，不用瀑布流**：同屏每列宽度一致、行距单独给（列距 24 / 行距 36 这类）；
      瀑布流只用于「图片高度本身就是信息」的站（Unsplash 类），列表/作品集不用
- [ ] **长图墙的顶栏 sticky**：顶栏 + 分类/筛选条合并成一个 sticky 块（≤112px），滚三屏后筛选还在
- [ ] **两级分类靠形状分层**：一级文字 tab（带短下划线选中态）、二级胶囊，两排并列时不靠颜色深浅区分
- [ ] **次级文字不低于 `#6b6b6b`**（白底 4.9:1）；`#888`（3.54:1）`#999`（2.85:1）都不合格
- [ ] 所有 `text-overflow: ellipsis` 都配了 `title` 或 tooltip，截断后信息可恢复
- [ ] **没有横向滚动**：390px 宽下 `document.documentElement.scrollWidth === window.innerWidth`，
      图墙重排成两列而不是「PC 版缩小」
- [ ] 每层背景只靠明度差 + 1px 边框分界，没有「阴影 + 粗边框 + 渐变」三重叠加
- [ ] 分界方式统一：同一层里不会一张卡靠边框、一张卡靠阴影（两派都行，混用才廉价）
- [ ] 圆角每一档都有归属（控件 / 卡片 / 暗卡 / 标签），没有「这个 10px 是随手写的」
- [ ] 内容区有最大宽度，超宽屏不拉成一条长线
- [ ] 首屏没有明显空白区（说明内容没加载或布局塌了）
- [ ] **浏览器原生表面**都碰过：`::selection`（与品牌色同族、别用系统蓝）、`caret-color`、`scrollbar`（细或隐）、
      `:focus-visible`（描边而非默认 outline，且不被 `overflow: hidden` 裁掉）、`text-underline-offset`、数字用 `tabular-nums`
- [ ] **depth 三选一**：卡片分界只用了「发丝圈 / 边距 / 阴影」其一；没有幽灵卡（白底白卡只靠一点模糊阴影分辨）
- [ ] **三把锁没破**：整页一个主题（无中途反色）、一个强调色、一套圆角系统
- [ ] **hero 四条**：标题 ≤ 2 行 / 副文案 ≤ 20 词 / 主 CTA 不滚动可见 / 顶部内边距 ≤ 6rem；
      没有版本号、装饰文字条、滚动提示、CTA 下方小字
- [ ] **eyebrow 密度** ≤ ⌈节数 ÷ 3⌉（产品站为 0），且全站风格统一（要么都对 `tracking`、要么都不对）
- [ ] **每节内容形态**：标题 ≤ 8 词 + 副段 ≤ 25 词 + 一个视觉或 CTA；没有连续三节同样的图文分栏
- [ ] **动效都有动机**（层级 / 叙事 / 反馈 / 状态变化之一），能被一句话说清；`prefers-reduced-motion` 下全部塌缩
- [ ] **multi-< 768px 显式塌缩**：每个多列网格都有对应断点，没有靠 `min-width` 硬撑
- [ ] **图片是真图**（生成 / picsum / 真素材），没有 div 拼的假产品 UI；logo 墙只有 logo 且是真 SVG
- [ ] **动效四问都有答案**：动机（层级/叙事/反馈/状态）？时长取自五档（120/180/240/400/600）？三档降级（完整/减弱/关闭）？只动 `transform`/`opacity`？
- [ ] **按下有反馈、hover 只两笔**：`translateY(1px)` 或厚度归零；卡片 hover 不超过「色 + 缩放其一」
- [ ] **没有 `window.addEventListener('scroll')` 驱动的布局或动画**；入场用 `IntersectionObserver`，进度用 `animation-timeline`
- [ ] **无限循环每页 ≤ 1**，且 hover / focus / `prefers-reduced-motion` 能停；数字滚动只给真实数据且只滚一次
- [ ] **6× CPU 节流下不掉帧、Paint flashing 无整块重绘**；`will-change` ≤ 3 且动画后撤销
## 二、内容与状态

- [ ] 每个数据区都有 **加载 / 空 / 错 / 无权限** 四种状态，且文案不同
- [ ] 加载态是骨架屏或与最终布局一致的占位，不是全屏遮罩转圈
- [ ] 空态有一个明确的主行动按钮
- [ ] 错误态有一句人话 + 重试入口，没有把 `Error: 500` 直接甩给用户
- [ ] 长文案、超长单词、超多行都试过：不会撑破容器、不会盖住别的元素
- [ ] 空数据和满数据（100 行）都看过
- [ ] 中文标点正确（。、，《》），没有中英标点混用

## 三、脚本（必须全跑）

```bash
node <skill>/scripts/screenshot.mjs --url <url> --out .design/after --themes light,dark
node <skill>/scripts/audit.mjs --url <url> --themes light,dark --expect-text "<目标页特征文案>"
python <skill>/scripts/contrast_check.py <css 目录或文件> --json contrast.json   # 传目录会递归找 *.css；路径写错直接退出 2，不会假通过
node <skill>/scripts/hygiene.mjs
node <skill>/scripts/run_checks.mjs    # 仅当项目有 package.json；静态站（scaffold 生成物）会明确提示跳过并退出 0
```

- [ ] `audit.mjs` 退出码 0（error 清零；残留 warn 每条都有解释）
- [ ] 深色主题单独跑过截图与审计，不是「浅色过了就完事」
- [ ] `contrast_check.py` 无未达标项：正文 ≥4.5:1，大字/图标 ≥3:1（发丝边框只打 `info` 不计入失败；`--_*` 私有变量不参与配对）
- [ ] `run_checks.mjs` 全绿：lint / typecheck / test / build（**仅当项目有 `package.json`**；静态站跳过）
- [ ] `hygiene.mjs` 的待确认项逐条看过并记录取舍（不要静默忽略）
- [ ] `before/` 与 `after/` 截图都留了，能指给评审看
- [ ] 若按参考站/设计稿的调性做：`probe-ref.mjs` 量过对方数值，关键取值能在
      `references/design-evidence.md` 的同行区间里找到依据（营销站的大标题不要搬进后台）

## 四、键盘与辅助技术

- [ ] Tab 键从页面顶部走到底：焦点顺序符合阅读顺序，没有跳过可交互元素
- [ ] 焦点态清晰可见（`:focus-visible` 有 2px 轮廓或等效的明显样式）
- [ ] 没有 `outline: none` 且无替代焦点样式的情况
- [ ] 弹窗/抽屉：打开时焦点移入，Esc 能关，关闭后焦点回到触发元素
- [ ] 所有图标按钮有 `aria-label` 或 `title`（`audit.mjs` 的 `icon-button-no-label`）
- [ ] 表单控件都有关联 `<label for>` 或 `aria-label`；错误用 `aria-describedby` 关联
- [ ] 图片有 `alt`（纯装饰用 `alt=""`）
- [ ] 尊重「减少动效」：prefers-reduced-motion: reduce 下装饰动画停下来
- [ ] 逐字/逐行入场这类滚动动画有静态回退，且移动端直接关掉
- [ ] **滚动动画的双份文字层**：非当前层 `aria-hidden="true"` 且 `opacity: 0`（否则残影 + 读屏读两遍）
- [ ] 按钮 hover / active 都有可见反馈（按下要真的「陷进去」，不是只换个色）
- [ ] **标题标签与视觉大小一致**：不许 `<h2>` 比 `<h3>` 小；眼睛标用 `<p>`/`<span>`，不占标题层级

## 五、响应式与移动端

- [ ] 390px 宽：单手可达区（屏幕下 1/3）放了主要操作
- [ ] 390px 宽：点击区 ≥44×44px（`audit.mjs` 的 `small-tap-target` 按 44 卡；正文里的行内文字链接按 WCAG 2.5.8 豁免，复选框按包裹它的 `label` 量）
- [ ] 表格在窄屏变成卡片列表或精简列，没有硬缩到看不清
- [ ] 输入框聚焦时键盘不遮挡字段（滚动到可见）
- [ ] 底部固定元素避开了安全区：`env(safe-area-inset-bottom)`
- [ ] 用了 `100dvh` 而不是 `100vh`（移动地址栏跳变）
- [ ] 文字缩放 200% 后不重叠、不裁切
- [ ] 触屏上 hover 效果不会粘住（`@media (hover: hover)`）

## 六、品牌与资产

- [ ] Logo 长宽比正确（`logo-distorted` 无报错），没有硬拉
- [ ] 深色主题下 Logo 可见（有深色版或底色容器）
- [ ] favicon 存在且不是默认 1px/破损（浏览器标签页里看一眼）
- [ ] 图标同源、同线宽、同网格，没有混用两套图标集
- [ ] 每张图有固定尺寸或 `aspect-ratio`，CLS ≤0.1
- [ ] 静态资源单文件 ≤300KB（hygiene.mjs 的 heavy-asset）
- [ ] 没有预载用不到的字体：document.fonts 里每一项都是 loaded 且在页面上真出现了
- [ ] 图片有 `loading` / `decoding` 策略，首屏图和其余图分开

## 七、代码卫生

- [ ] 一个提交只做一类事（调色 / 布局 / 状态 / 可用性分开）
- [ ] 没有新增 `!important`；没有用 `margin-left` 硬推位置
- [ ] 颜色、间距、字号走令牌，没有散落在组件里的魔法值
- [ ] 没有为了对齐而写死 `height`（内容变多就溢出）
- [ ] 没有引入第二套样式体系（Tailwind 项目里没塞 CSS-in-JS）
- [ ] 新代码风格和旁边文件一致（命名、目录、单位、注释密度）
- [ ] 无引用组件/资源/样式已清理或说明保留原因
- [ ] 促销/公告区与主设计语言有边界：没有把活动配色渗进主按钮体系
- [ ] 没有把设计稿的 px 原样搬进来（先确认稿子是几倍图）

## 八、交付说明（四段，缺一段不算交付）

```
改了什么：<3–5 条，按影响面排序>
为什么：<每条一句，指向具体问题与量化证据>
验证：<命令 + 结论 + 截图路径>
未做与风险：<没改的、需要产品/设计定的、已知局限>
```

- [ ] 给出了 before/after 截图路径，而不是口头描述
- [ ] 量化了关键改善（对比度 3.1→4.6、横向溢出 42px→0、CLS 0.24→0.02）
- [ ] 明确列出「没做」的部分，不让评审以为已全覆盖
- [ ] 遇到的取舍写清理由（为什么保留某个 warn、为什么没换图标集）

## 九、陈列类页面（风格库 / 模板库 / 图墙 / 灵感库）额外九条

- [ ] **预览是活的，不是截图**：每张卡用条目自己的 CSS 渲染；截图版一律打回。
- [ ] **预览整体缩放而非缩字号**：`container-type: inline-size` + `scale(calc(100cqw / 基准宽))`；
      390 宽下预览文字仍 ≥10px 且不被裁。
- [ ] **预览 DOM 有 `aria-hidden="true"`**，可点区域只有一个覆盖整卡的 `<a>`；
      读屏不该念 N 遍展品文字。
- [ ] **卡片高度公式一致**：预览比例 + 色板高度 + 文本区高度三个数字定死；
      直角体系下（`radius: 0` 陈列区）尤其必须，否则参差会被放大。
- [ ] **可点就有反馈，键盘也要有**：卡片 / 图版必须有 hover（环加深、图微提亮、标题下划线，三笔之内）+ `:focus-visible` 同款；
  反例是 Muzli 的卡片——`transform` / `filter` / `box-shadow` / 文字色 hover 前后完全一致，`:focus-visible` 也没有额外样式。
- [ ] **hover 有反馈且只有必要的那几笔**：边框转深 + 标题转强调色够用；
      图本身零反馈（站酷的反面）同样不合格。
- [ ] **色板条四段成对**：背景/前景/强调/辅色固定四段，别因条目只有三个色就变三段。
- [ ] **视觉裁切有出口**：内容被裁（只露 1.8 张 / 截断整行）时，必须给「+N」、hover 提示或键盘可达的「查看全部」；
      裁了却不提示，等于内容丢失。
- [ ] **素材型陈列不画壳**：当条目本身就是成品（真机截图 / 照片 / 实物图）时，不加卡片底、边框、阴影，
      靠比例统一 + 列距分版；给每张图套壳是本类最常见的「AI 味」。
- [ ] **一个正方形尺寸走全场**：头像/图标/缩略图共用一个尺寸档，两处不一致（例 72 与 80）就算没对齐。

## 十、红旗（出现就别交付）

- 只做了浅色 / 只做了 1440 宽 / 只做了 happy path
- `audit.mjs` 退出码非 0 却说「基本没问题」
- 删了组件或资源但没有核实引用（hygiene 结果是待确认，不是命令）
- 用 `outline: none` 换来了「更干净」的观感
- 深色主题是把浅色反色得到的，没有单独校验对比度
- 截图是手动截的，且只有一张，评审无法验证其他视口/主题
- 构建或测试本来就是红的，却把「改前也红」当理由
- 深色开关点了没效果（按钮存在、令牌没换）——有开关不生效比没有开关更伤
- 陈列类页面用截图当卡片预览，或预览里的真文字被 `overflow: hidden` 裁成半行
- 无限滚动只显示「已显示 N / M」，没有「加载更多」也没有分页——键盘与读屏用户到不了下一批
- 用 `viewport width=1420`（或任何锁宽值）当移动端：390 屏上整站缩到 30% 以下，正文物理高度不足 6px
- 内容站没有 `<h1>`、也没有页脚（备案 / 隐私 / 联系），最大的字靠 `div` 撑
- 全站只有一个行高 `normal`，却用来排超过 40 字的中文段落
