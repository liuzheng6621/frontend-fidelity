# Vercel 注册页：390px 表单列与五档圆角阶梯

> 采样日期：2026-10-27；对象为 <https://vercel.com/login> 与 <https://vercel.com/signup> 公开页面，不登录、不提交表单。
> 视口：桌面 1440×900、移动 390×844（`isMobile` + `hasTouch`），各一次；未做断点扫描。
> 读法：尺寸为当次计算样式与盒模型实测；社交登录按钮数量与第三方可用性会变，不作为设计令牌。

## 一、证据范围与纠偏

- 通用探针：登录页 74 个计量元素、6 张图；注册页 72 个元素、30 张图；两端各一次。
- 定向脚本只量了标题、按钮、输入框与最宽容器，**没有**量第三方登录弹窗、验证码页与错误态。
- 两页都是首屏一屏高（`scrollHeight === 900`），没有长页可量版式节奏；本文的「节奏」只有标题→按钮组→页脚三段。
- `input` 探针命中 0 个：登录/注册的邮箱输入是点「Continue with Email」后才渲染的第二步，本次未自动点击，**输入框尺寸未验证**。
- Linear 登录页 `linear.app/login` 同步采了一份，作为「单列表单两端同构」的对照组，不是主参考。

## 二、关键实测数字

| 部位 | 桌面 1440 | 移动 390 | 复用口径 |
| --- | --- | --- | --- |
| 表单列宽 | **390** | **326**（视口 − 32） | 登录类页面是一根窄列，不是居中卡片 |
| 主标题 h1 | 32 / 40 / 600 | **24 / 32 / 600** | 两端都只降一档，不靠 clamp |
| 正文 / 说明 | 13 / 16 / 400（1.23） | 13 / 16 / 400 | 说明文字比按钮小 3px，层级靠字号不靠颜色 |
| 社交登录按钮 | 390 × 40，r8 | 326 × 40，r8 | **高度不变**，只改宽度 |
| 按钮内边距 | `0 14px` | `0 14px` | 不随宽度缩放 |
| 按钮字 | 16 / 24 / 500 | 16 / 24 / 500 | 40 高配 16 字，不是 14 |
| 控件高 | 40 | 40 | 全站单一档，没有 sm/md/lg |
| 圆角 | 8 / 6 / 4 / 2 / 12 | 同 | 五档全在，但主按钮只用 8 |
| 间距 | 8 / 16 / 24 / 32 | 同 | 4 的倍数，最小 8 |
| 页面高 | 900（恰好一屏） | 844（恰好一屏） | 不做出滚动条的登录页 |

对照组 Linear `linear.app/login`：19 个元素，字阶只有 13 / 18 两档，按钮 13px / 控件高 **44** / 圆角 **9999（胶囊）**，390 与 1440 数值完全一致——它的登录页本身就是固定窄列，不存在重排。

## 三、色板

| 角色 | 实测值 | 用途 |
| --- | --- | --- |
| 页面底 | `#fafafa` | `body` 背景 |
| 卡/按钮底 | `#ffffff` | 社交登录按钮、内容卡 |
| 主文字 | `#171717` | 标题、按钮文字 |
| 次级文字 | `#4d4d4d` | 说明段 |
| 更弱文字 | `#a8a8a8` | 页脚条款 |
| 品牌蓝 | `#0072f5` | 链接与强调 |
| 深色块 | `#171717` | 注册页的深色强调面 |

- 社交登录按钮是**白底 + 无边框 + 无阴影**，靠 `#fafafa` 页面底衬托出来；不是「灰底按钮」。
- 深色强调面与主文字同色（`#171717`），没有第二套黑。
- 单层阴影，探针记到 1 张卡 1 层阴影；标题与按钮组之间没有分割线。

## 四、字阶

| 档 | 字号 / 行高 / 字重 | 用在哪 |
| --- | --- | --- |
| 32 | 32 / 40 / 600 | h1（1440） |
| 24 | 24 / 32 / 600 | h1（390） |
| 16 | 16 / 24 / 500 | 按钮 |
| 14 | 14 / 21 / 400 | 正文段 |
| 13 | 13 / 16 / 400 | 说明、页脚 |
| 12 | 12 / 16 / 400 | 极小注 |

- 只有 **6 档**，且 16 与 14 是两套用途（按钮 vs 正文），不是同一档的两个变体。
- 行高比集中在 1.23–1.33，比内容站紧；登录页不需要阅读舒适度，需要一屏装下。
- 字重只有 400 / 500 / 600 三档，没有 700。
- 字体 `GeistSans`（自托管变量字体），无系统栈回退声明，也就没有中文回退——中文场景要自己补一档。

## 五、表单列与间距

- 桌面 1440 下表单列固定在 **390px**，居中，两侧各留 525；移动端变成 `视口 − 32`（左右各 16）。
- 390 是这套设计里唯一的「内容宽度」常量：社交登录按钮、表单卡、标题都对齐这条线。
- 移动端**不复用** 390，而是撑满减边距——说明它把 390 当作「桌面上的窄列」，不是「移动端宽度」。
- 间距只有 8 / 16 / 24 / 32 四档；按钮之间 8，区块之间 24–32。
- 没有 12 和 20：这套间距是 8 的倍数体系，不是 4 的倍数体系。

## 六、组件配方

**社交登录按钮**（页面主体，5 个同规格）：

```css
.sso {
  width: 100%;            /* 桌面 390，移动 326 */
  height: 40px;
  padding: 0 14px;
  border: 0;
  border-radius: 8px;
  background: #fff;
  color: #171717;
  font: 500 16px/24px GeistSans, sans-serif;
}
```

**次级按钮**（Show other options）：同尺寸，`background: transparent`，没有边框，靠文字色区分。

**主标题**：

```css
.auth h1 { margin: 0; font: 600 32px/40px GeistSans; letter-spacing: -0.02em; }
@media (max-width: 600px) { .auth h1 { font-size: 24px; line-height: 32px; } }
```

**表单列**：

```css
.auth__col { width: 390px; margin: 0 auto; }
@media (max-width: 600px) { .auth__col { width: auto; margin: 0 16px; } }
```

## 七、两步流程（注册的实际路径）

1. 首屏只有「Continue with X」五个按钮 + 一行「Show other options」；没有输入框。
2. 点 Email 之后才出现邮箱输入 → 提交 → 验证码/邮件确认。
3. 本次按「不提交表单」的采样约束，**没有**进入第 2、3 步，因此验证码长度、错误提示、返回按钮位置都未验证。

可迁移的形状：**把第三方登录放前面、邮箱登录藏在次级入口**，首屏一屏装完；这个顺序本身就是设计决策，不是默认。

## 八、它没做好的

1. **输入框全程未出现在首屏**，自动化与手测都要多一步点击才能看到表单——对「无障碍自动化」不友好。
2. **中文字体缺回退**：`GeistSans` 单栈，中文环境会掉到浏览器默认（本项目实测时页面是英文，未触发；中文站照抄会露馅）。
3. **控件高只有 40 一档**：移动端触控下限按 44 算，40 略欠，靠点击区加 padding 补。
4. **没有可见的输入框焦点样式证据**（元素未渲染），不能断言它有 `focus-visible`。
5. **页脚条款字 12px / #a8a8a8 对白底约 2.4:1**，不足 4.5:1——装饰性条款常被豁免，但严格审计会报。

## 九、能搬 / 不能搬

能搬：

- 390px 窄列 + 移动端「撑满减 32」的两段式，比 clamp 更好预测。
- 按钮 40 高配 16px/500 字，社交登录 5 个同规格排一列。
- 间距 8/16/24/32 四档、圆角 8/6/4/2/12 五档——两套都是有限集合。
- 标题 32→24 只降一档，不做流体字号。

不能搬：

- 先社交后邮箱的顺序（面向开发者产品才成立；企业后台通常要把账号密码放前面）。
- `#fafafa` 底 + 纯白按钮的对比（在低亮度屏上按钮边界几乎消失，本项目审计会报「按钮与背景对比不足」）。
- 单字体无中文回退。
- 12px 浅灰条款文字。

## 十、复现清单

1. 建一根 390px 窄列，`margin: 0 auto`；`max-width: 600px` 断点内改成 `margin: 0 16px; width: auto`。
2. 标题 32/40/600，断点内 24/32/600，加 `letter-spacing: -0.02em`。
3. 按钮统一 40 高、`padding: 0 14px`、r8、16/24/500；主按钮白底或品牌蓝二选一，不要中途换。
4. 间距只用 8/16/24/32；按钮纵向 gap 8，区块间 24 或 32。
5. 第三方登录最多 4 个一列，第 5 个起收进「更多方式」。
6. 补中文字体回退与 `focus-visible`（本站未提供证据，属必须自补项）。
7. 用 `flow.mjs` 把「填邮箱 → 提交 → 出现验证码输入」写成流程，补上本文未验证的第 2、3 步。

## 十一、和 Linear 登录页的差异

| | Vercel | Linear |
| --- | --- | --- |
| 元素数 | 72 | 19 |
| 控件高 | 40 | 44 |
| 圆角 | 8（按钮） | 9999（胶囊） |
| 字阶 | 6 档（12–32） | 2 档（13 / 18） |
| 两端差异 | h1 32→24 | 完全一致 |
| 结论 | 有一套完整令牌的登录页 | 几乎是「一个胶囊按钮 + 一行字」，靠留白撑 |

做 B 端登录页时，Vercel 更像「可抄的规格」，Linear 更像「可以更少」的证据。两者都不适合直接搬进中文企业后台——它们都没有中文排版证据。

## 结构证据（REA 被动采集，2026-10-31）

> 采集地址 `https://vercel.com/login`，1440×900 无头 Chromium，CDP 被动读 DOM 与无障碍树：不执行脚本、不点击、不导航。
> 数字是采集时刻的快照，样式数值见 `references/design-evidence.md`；本层只回答「结构怎么搭」。

| 指标 | 值 |
| --- | --- |
| DOM 节点 | 413 |
| 无障碍节点 | 123 |
| DOM 深度（最大 / 均值） | 16 / 6.1 |
| 地标 | 6 个：`banner` / `main` / `navigation` / `form` / `form` / `navigation` |
| 标题层级 | h1×1 |
| 语义标签 | `header`×1 `nav`×2 `main`×1 `footer`×1 `form`×2 |
| 带 aria-* 的元素 | 15 |
| 图片 alt 覆盖 | 6/6 |
| 链接 / 图片 / 按钮 / 标题 | 6 / 4 / 8 / 1 |
| 标签频次 Top 6 | `script`×127 `link`×40 `div`×27 `span`×22 `meta`×14 `button`×7 |

**判读**：413 个 DOM 节点配 127 个 `<script>`——**壳极薄、逻辑极重**，DOM 深度均值 6.1（全部样本里最浅）。6 个地标里 **有 2 个 `form`**：邮箱登录与 SSO 分成两块独立表单，各自带地标名，屏幕阅读器可以直接跳。整页只有 1 个标题（`h1`），因为它只有一个任务。
