# 反模板手册（anti-slop）

**这份文件回答一个问题：为什么这套界面一看就是 AI 做的，怎么把它救回来。**

来源是 `design-taste-frontend`（1,206 行单文件规则集）的蒸馏，只保留可执行的部分，并按本站实测语料补了中文站条款与裁决（裁决在 `references/craft-floor.md` 第八节，本文不重复）。

边界（先读）：
- **适用于**：落地页、产品营销页、作品集、重设计、单页展示。
- **不适用于**：后台与数据密集产品 UI（那走 `page-patterns.md` 的管理端骨架 + 官方设计系统）、数据表格、多步表单、代码编辑器、原生 App。
- 每条规则都是**有条件**的：先读需求，再决定哪条开火。没有一条是"永远这么做"。

---

## 一、动手前：一句话 Design Read

先推断用户在要什么，再动手。模型出烂设计的根本原因是**跳过读需求、直接跳到默认审美**。

要读的六个信号：

| 信号 | 看什么 |
|---|---|
| 页面种类 | 落地（SaaS / 消费 / 机构 / 活动）、作品集（开发 / 设计 / 工作室）、重设计（保身份 vs 换世界）、编辑型 |
| 气质词 | "极简"、"克制"、"Linear 那种"、"Awwwards"、"野兽派"、"高级消费"、"Apple 味"、"serious B2B"、"编辑感"、"暗黑科技" |
| 参照物 | 用户给的 URL、截图、竞品名 |
| 受众 | 采购评审 vs 设计敏感的消费者 vs 扫简历的招聘方——**受众定审美，不是你的口味** |
| 已有资产 | logo、色、字、摄影；重设计时这些是起点，不是可选项 |
| 隐性约束 | 无障碍优先、公共部门、受监管行业、信任优先、儿童产品——**这些压过审美偏好** |

然后输出一行，再写代码：

> Reading this as: `<页面种类>` for `<受众>`, with a `<气质>` language, leaning toward `<设计系统或审美家族>`.

例：
- 「B2B SaaS 落地页，技术买家，Linear 式极简，Tailwind + 系统栈 + 克制动效」
- 「独立设计师作品集，招聘方，编辑 / 动态字体，原生 CSS + 滚动驱动 + 自定义字体」
- 「公共部门服务改版，信任优先，GOV.UK 一类系统」

**只在真的分叉时问一个问题**（"要更像 Linear 的干净，还是更像 Awwwards 的实验？"），能推断就别问。

**反默认清单**：不要一上手就是 AI 紫渐变、深色 mesh 上的居中 hero、三张等大功能卡、到处都是毛玻璃、每处都在循环的小动画、Inter + slate-900。这些是模型的默认答案，要**刻意绕开**。

## 二、三个旋钮（把"气质"变成数字）

先设三个数，后面每条布局/密度/动效决定都受它们约束。

- `DESIGN_VARIANCE` 1–10：1 = 完美对称，10 = 艺术性混乱
- `MOTION_INTENSITY` 1–10：1 = 静态，10 = 电影级
- `VISUAL_DENSITY` 1–10：1 = 画廊般疏，10 = 驾驶舱般密

**基线 8 / 6 / 4**，除非 Design Read 覆盖。

| 信号 | VARIANCE | MOTION | DENSITY |
|---|---|---|---|
| 极简 / 干净 / 克制 / 编辑 / Linear 式 | 5–6 | 3–4 | 2–3 |
| 高级消费 / Apple 味 / 奢侈 / 品牌 | 7–8 | 5–7 | 3–4 |
| 玩趣 / 实验 / Dribbble / Awwwards / 机构 | 9–10 | 8–10 | 3–4 |
| 落地页 / 作品集 / 营销站（默认） | 7–9 | 6–8 | 3–5 |
| 信任优先 / 公共部门 / 受监管 / 无障碍关键 | 3–4 | 2–3 | 4–5 |
| 重设计 · 保身份 | 同现状 | +1 | 同现状 |
| 重设计 · 换世界 | +2 | +2 | 同现状 |

**与本站三套人格的对照**（`design-tokens.md` 里的 `rational` / `editorial` / `warm`）：

| 人格 | VARIANCE | MOTION | DENSITY | 对应实测站 |
|---|---|---|---|---|
| `rational` | 3–5 | 2–4 | 6–7 | shadcn、linear、cal.com、jsdesign（后台侧） |
| `editorial` | 6–7 | 3–5 | 3–4 | stripe、stylekit、zcool |
| `warm` | 6–8 | 5–7 | 4–5 | duolingo、wegic（营销侧）、uinotes |

旋钮的**读法**（用来判断"该不该动"）：

- VARIANCE 1–3：12 栏等分、等内边距、居中。4–7：`margin-top: -2rem` 重叠、混比例图（4:3 挨着 16:9）、左对齐标题配居中数据。8–10：masonry、`grid-template-columns: 2fr 1fr 1fr`、大留白（`padding-left: 20vw`）。
- MOTION 1–3：只有 `:hover` / `:active`。4–7：`transition: .3s cubic-bezier(.16,1,.3,1)` + 入场 `animation-delay` 级联。8–10：滚动驱动 / ScrollTrigger / 视差。
- DENSITY 1–3：`py-32`～`py-48`。4–7：`py-16`～`py-24`。8–10：无卡片、1px 线分隔、数字全 `tabular-nums`。

**一致性铁律**：`MOTION_INTENSITY > 4` 就必须**真的有动效**（hero 入场、关键节滚动显现、CTA hover 物理反馈），不能只在文档里声称 7 而页面是死的；反之，交付范围里做不出稳定动效，就把旋钮降到 3，交一个干净的静态页。**半成品动效（截断的 ScrollTrigger、抖的入场、没清理的监听）比没有更糟。**

## 三、用真系统还是做气质

需求能对上一个**官方包**，就装官方包，不要手工复刻它的 CSS，也不要导入了令牌却覆盖掉 90%。

| 需求读起来像 | 用 |
|---|---|
| 微软 / 企业 SaaS / 后台 | `@fluentui/react-components` 或 `@fluentui/web-components` |
| Google 味 / Material | `@material/web` + Material 3 令牌 |
| IBM 式 B2B / 分析 | `@carbon/react` + `@carbon/styles` |
| Shopify 应用界面 | Polaris（web components / React） |
| Atlassian / Jira 式 | `@atlaskit/*` + `@atlaskit/tokens` |
| GitHub 式开发工具 / 社区页 | `@primer/css`（产品或 `@primer/react-brand` 营销） |
| 英国公共部门 | `govuk-frontend`（法律/监管预期） |
| 美国公共部门 / 信任优先 | `uswds` |
| 本地生意 / 机构 MVP | Bootstrap 5.3 |
| 现代无障碍 React 底座 | `@radix-ui/themes` |
| 你自己拥有组件的现代 SaaS | shadcn/ui（**别交默认态**） |
| 独立/小团队 Tailwind 路线 | Tailwind v4 |

**一个项目只用一个系统。**不要把 Fluent 和 Carbon 混在一个树里。

**当需求是一种"气质"而不是系统**（毛玻璃、Bento、野兽派、编辑、暗黑科技、极光渐变、动态字体），**没有官方包**：用原生 CSS + 维护良好的组件库做，并在注释里诚实标注哪些是"借鉴的灵感"、哪些是"官方材料"。

- 毛玻璃：`backdrop-filter` + 分层边框 + 高光叠层，并给 `prefers-reduced-transparency` 的实底回退。
- Bento：CSS Grid 混格尺寸，没有库拥有它。
- 极光/mesh：SVG 或分层径向渐变。
- **Apple Liquid Glass**：Apple 只为 Apple 平台定义它，**网页端没有官方 `liquid-glass.css`**，网页实现是近似，必须标注为近似。

## 四、硬布局规则（违反其中任何一条都算没做完）

### 4.1 hero 必须装得进首屏

- 标题桌面端 **≤ 2 行**；副文案 **≤ 20 词且 ≤ 4 行**；CTA **不用滚动就看得见**。
- 文案太长的正确解法是**砍文案或降字号**，不是让 hero 溢出。20 词说不清价值主张，说明价值主张没想清。
- **字号与图要一起规划**：图大且标题超 6 词，就别从 `text-7xl/8xl` 起。常规 `4xl/5xl/6xl`；只有 3–5 词的标题才到 `6xl/7xl`。**四行 hero 标题永远是字号错，不是文案错。**
- **顶部内边距上限 6rem**（`pt-24`）。超过就是"内容浮在视口半腰"，读起来像布局 bug。想要呼吸感请加大字号或图，而不是加内边距。
- **hero 最多 4 个文字元素**：eyebrow 或品牌条（二选一或都不要）/ 标题 / 副文案 / CTA（1 主 + 最多 1 次）。
- **hero 里禁止**：CTA 下方的极小说明行、信任微条（"已被 XX 团队使用"）、价格预告、功能 bullet、头像社交证明。这些全部移到 hero 下面独立成节。
- 「Trusted by / 客户 logo 墙」**放在 hero 下面**，永不塞进 hero 的同一行。

### 4.2 导航与页脚

- **桌面端导航必须单行**；放不下就砍标签、去次要项、或收进汉堡。两行导航 = 坏设计。
- **导航高度上限 80px**（常规 64–72）。不要"大机构"式巨栏吃掉 15% 视口。
- logo 墙**只放 logo**，不要在下面标行业（`Vercel / hosting`、`Stripe / payments`）——logo 本身就是可信度。

### 4.3 栅格与节奏

- **Bento 格子数 = 内容条数**。3 条内容就 3 格（1+2 / 2+1 / 不等三格），中间或末尾不能留空格；留空说明规划错了，重排，不要塞空块。
- **Bento 要有节奏**：不能连续 6 个"左图右文"。要交错全宽行、不等格尺寸、纵向断点。
- **Bento 背景要多样**：多格区域里至少 2–3 格有真实视觉变化（图 / 品牌渐变 / 纹理 / 有色底），不能全是白底白字的文本卡。
- **布局族不复用**：一旦某节用了某布局族（三列图卡 / 全宽引言 / 图文分栏），整页最多再出现一次；8 节的落地页至少用 4 种不同族。**"精选作品"不能长得像"我们做什么"。**
- **Z 字交替上限**：连续"左图右文 / 左文右图"最多 2 节，第 3 节必须换族（全宽、纵堆、bento、跑马灯……）。
- **split-header 默认禁**：左大标题 + 右小段说明的"分区头"是模板。一节只说一件事；真要解释段落，就**纵向堆**（标题在上、正文在下，≤ 65ch）。只有右列承载真实视觉/交互元素时才用两栏头。
- **eyebrow 密度**：见 `craft-floor.md` §8.1（密度 ≤ ⌈节数/3⌉，产品站不用）。
- **每节的多列布局必须显式声明 < 768px 的塌缩规则**，不能指望"Tailwind 会处理"。

### 4.4 三把锁（每把都要能通过机械核对）

| 锁 | 内容 | 核对方式 |
|---|---|---|
| **主题锁** | 整页只有一个主题。暗色页不能中间夹一段暖白，反之亦然（唯一的例外是"整页一次性主题切换"的明确编排） | 逐节看 `background` 家族 |
| **色锁** | 一个强调色用到底。暖灰站不会在第 7 节突然出现蓝色 CTA，玫瑰色站不会有青色徽标 | grep 强调色出现处的角色 |
| **形状锁** | 一套圆角系统：全直角 / 全柔（12–16）/ 全胶囊；混用必须有**成文规则**（"按钮全胶囊、卡片 16、输入框 8"）并全站遵守 | 量所有 `border-radius` 的分布 |

## 五、图片与"假截图"

落地页与作品集是**视觉产品**。纯文字页 + div 拼的假截图 = slop。

优先级：

1. **能用图生成就用图生成**（有 `generate_image` / MCP 图工具 / IDE 内生成就必须用），按节需要的比例生成 hero 图、产品图、纹理。
2. **用真图**：`https://picsum.photos/seed/<描述性种子>/<w>/<h>`（种子写清用途，如 `marrow-cookware-kitchen`）；或需求方给的真实素材；或明确允许的开放素材。
3. **都不行就告诉用户**：留 `{{TODO: hero 产品图 1600×1200}}`，并在回复里列出缺图位。**不要用 div 拼假 UI，也不要手搓 SVG 场景图。**

其他硬条款：

- **div 拼的假产品界面（假任务列表 / 假终端 / 假仪表盘）是头号 AI tell**，禁。要展示产品：真截图、生成图、或真实的迷你组件预览。
- **极简站也需要真图**：纯文字不是极简，是没做完。克制的编辑式站至少 2–3 张真图（hero、一张产品/生活、一张辅助）。
- **logo 墙用真 SVG**（Simple Icons / devicon）；自造品牌名就自造一个 monogram 标记，别用纯文字词标；明暗两种模式都要能看。
- **图片上不要压标签/胶囊**（`PLATE · BRAND`、`Field notes`）；要说明就在图下写一句功能说明。
- **不要装饰性图注**（`Field study no. 12 · Ines Caetano`）——除非真的在给真实摄影师署名。
- **营销页不要版本脚注**（`v1.4.2`、`Build 0048`、`last sync 4s ago`）。

## 六、AI tell 清单（分组，逐条可判）

这些是"生产测试"里反复出现的签名，都是模型的默认答案。要做得像人做的，先逐条灭掉。

### 6.1 hero 与顶部

- **hero 里的版本号**：`V0.6`、`BETA`、`INVITE-ONLY`、`EARLY ACCESS`（除非需求就是发布/预览状态）。
- **"品牌 · No. 01" 式子 eyebrow**。
- **hero 底部的装饰文字条**：`BRAND. MOTION. SPATIAL.`、`TYPE / FORM / MOTION`、`ESTD. 2018 · LISBON · …`。除非这条真的能点（粘底导航）或承载真实状态（cookie / 构建信息）。
- **滚动提示**：`Scroll`、`↓ scroll`、`Scroll to explore`、鼠标滚轮图标。用户知道怎么滚。
- **地名/时间/天气条**：`Lisbon, working with founders`、`LIS 14:23 · 18°C`。除非真的是分布式工作室或有实体地址，否则是装饰。页脚写一行联系地址是允许的。

### 6.2 编号与微标签

- **小节编号当 eyebrow**：`00 / INDEX`、`001 · Capabilities`、`06 · how it works`。
- **`01 / 4` 式分页**贴在图上或 bento 格上——用户数得出来，不需要标签。
- **`Index of Work, 2018 - 2026` 式区间标签**。直接说这节是什么。
- **通用步骤标签**：`Stage 1 / Step 1 / Phase 01 / Pass One`。用动词本身当标签（"安装"、"配置"、"上线"），别写"第一步：安装"。

### 6.3 分隔符与状态点

- **中点 `·` 要限量**：一行元数据最多 1 个，别把它当万能分隔符（`foo · bar · baz · qux`）。
- **装饰性彩色状态点**：每个导航项、每行列表、每个徽标前都点一个色点 = tell。只有当它承载真实语义（服务状态、可约状态）时才允许，且每节最多一个。

### 6.4 排版花招

- **`<br>` 断行 + 斜体词**的"设计感"标题（`for thirty<br>*years.*`）。先让标题自然读通，再谈巧。
- **竖排旋转文字**（`INDEX OF WORK` 转 90°），除非是机构/实验站且真的服务构图。
- **十字/细线网格当装饰**。线只在组织真实内容时画。
- **斜体降部裁切**：斜体展示字里出现 `y g j p q`，`leading-[1]` 会切掉降部——**行高至少 1.1，并给包装元素留 `pb-1`**。
- **假精确数字**：`99.99%`、`50%`、`1234567` → 用有零头的真实感数据（`47.2%`），或标成示例。

### 6.5 文案与命名

- **通用人名**：John Doe、Sarah Chan → 用符合地区与场景的真名。
- **通用头像**：SVG 蛋形 / lucide 用户图标 → 用可信的真人占位或明确风格化处理。
- **创业味品牌名**：Acme、Nexus、SmartFlow、Cloudly → 造有场景的真实名。
- **空动词**：Elevate、Seamless、Unleash、Next-Gen、Revolutionize → 换具体动词。
- **做作文案**：`Quietly in use at`、`From the field`、`Currently on the bench`、`Loose plates` 这类诗意标签 → 用平实的（"客户"、"最新文章"、"正在做"）。
- **eyebrow 下面的微元句子**（"这些都是我们今天上线的功能，不是路线图承诺"）→ 删，eyebrow + 标题 + 正文已经够了。
- **文案自检（交付前必做）**：把页面上每一句可见文字重读一遍，抓出**语法断裂**、**指代不明**、**像 AI 幻觉的机灵话**、**假装谦逊**。抓到的全部改成平实句。**AI 式的机灵比无聊更糟。**

### 6.6 假预览与假数据

- div 拼的假产品 UI（见第五节）。
- 假截图里的假版本脚注。
- `Reservation 412 of 800` 式假库存计数器（除非真有实时数据）。

### 6.7 面板、评分条与长列表

- **长列表 / 规格表每行都带 `border-t` + `border-b`**：选一种，用稀疏一点。10 行规格表每行一条发丝线是最懒的布局。
- **带填充底槽的评分条/进度条**当对比视觉（`bg-zinc-200` 槽 + 局部填充）。要对比就给数字 + 小图标，或给一条**没有底槽**的细条。
- **数据倾倒区**：落地页放 20 行发布表 / 30 行获奖名单 / 巨型价格矩阵 = 布局错。改成 3–5 条高亮 + "查看完整列表"，或换页。

### 6.8 动效

- 每个卡片都在无限循环（pulse / float / shimmer / 轮播）。**信息节保持静止。**
- 不能一句话说清"这个动画在传达什么"（层级 / 叙事 / 反馈 / 状态变化）的，删掉。
- 跑马灯整页最多一处。
- 反对 `window.addEventListener('scroll')`：它每帧都跑、易卡顿。用 `IntersectionObserver` / CSS `animation-timeline` / 库的 scroll hook。
- 只动 `transform` 和 `opacity`；别动 `top/left/width/height`。`will-change` 只给真会动的元素。
- **`MOTION_INTENSITY > 3` 必须尊重 `prefers-reduced-motion`**：无限循环、视差、滚动劫持、磁性物理都要塌缩成静态。
- **别把 GSAP/Three 和别的动效库混在同一个组件树里**（抢同一批帧）。

## 七、中文站的额外条款（原文没有，本仓补）

英文规则集里有几条在中文语料里要改写，否则会照成笑话：

| 原条款 | 中文站怎么落 |
|---|---|
| **em-dash 全禁** | 中文用「——」，且**一页最多 2 处**；不要用 `—` 当分隔符（中文里那是破折号误用）。范围用「～」或「-」 |
| 弯引号优先 | 中文用「」外层、『』内层（见 `copy-and-content.md`） |
| 中点 `·` 限量 | 中文元数据本来就用 `·`（`v2.5 · 2026.09`），一行一个够；**不要 `·` 和 `/` 混用** |

## 八、pre-flight（交付前逐条打勾）

不是可选项。有一条打不上，就还没做完。

**需求与方向**
- [ ] Design Read 一句话写出来了？
- [ ] 三个旋钮显式给了值并说明理由（不是默默用基线）？
- [ ] 设计系统从官方包里选了，或明确标注"这是气质不是系统"？
- [ ] 如果是重设计：模式（保身份 / 换世界）判定过，现状审计做过？

**hero**
- [ ] 标题 ≤ 2 行，副文案 ≤ 20 词且 ≤ 4 行，CTA 不滚动可见？
- [ ] 顶部内边距 ≤ 6rem，内容没有浮在视口半腰？
- [ ] hero 文字元素 ≤ 4 个，没有"CTA 下方小字说明"和信任微条？
- [ ] 没有版本号、没有装饰文字条、没有滚动提示、没有地名条？

**结构与节奏**
- [ ] eyebrow 数量 ≤ ⌈节数/3⌉（产品站为 0）？
- [ ] 没有 split-header（左大标题 + 右小段）？
- [ ] 没有连续 3 节同样的图文分栏？
- [ ] 至少 4 种布局族（8 节页面）？
- [ ] bento 格子数 = 内容条数，无空格，且 2–3 格有真实视觉？
- [ ] 长列表（> 5 项）换了组件，不是 `<ul> + divide-y`？
- [ ] 导航单行、高度 ≤ 80px？
- [ ] 没有三张等大功能卡、没有 hero 三指标？

**三把锁与对比度**
- [ ] 整页一个主题，无中途反色？
- [ ] 一个强调色用到底？
- [ ] 一套圆角系统（或成文的混用规则）？
- [ ] 每个 CTA 文字对背景 ≥ 4.5:1，没有白字白底、没有无边的幽灵按钮？
- [ ] CTA 文案桌面端不换行（≤ 3 词，主 CTA 最好 1–2 词）？
- [ ] 同一意图只有一个标签（contact / signup / portfolio 各一个）？
- [ ] 表单：标签在上、placeholder 不当标签、错误在下、placeholder/焦点环/辅助文本都过 AA？

**图片与内容**
- [ ] 用了真图（生成 / picsum / 真素材），没有 div 假截图、没有手搓装饰 SVG？
- [ ] logo 墙只有 logo（没有行业标签）、用真 SVG、明暗都能看？
- [ ] 图上没有压标签，没有装饰性图注，没有版本脚注？
- [ ] 引语 ≤ 3 行，署名有角色（不是只有一个名字）？
- [ ] 每节的内容形态合规（标题 ≤ 8 词 + 副段 ≤ 25 词 + 一个视觉或 CTA）？
- [ ] 文案自检做过了（无语法断裂、无机灵话、无假精确数据）？

**动效与工程**
- [ ] 声称的动效做出来了（旋钮 > 4 时页面真的动）？
- [ ] 每个动画能一句话说明动机？
- [ ] 跑马灯 ≤ 1 处，无限循环没有铺满？
- [ ] 尊重 `prefers-reduced-motion`？
- [ ] 没有 `window.addEventListener('scroll')` 驱动的布局？
- [ ] 只用 `transform` / `opacity` 做动效？
- [ ] 多列布局显式声明了 < 768px 塌缩？
- [ ] 空 / 载入 / 错误三态都有？
- [ ] 一个项目只用一个设计系统？

## 九、怎么用这份文件

- **和 `craft-floor.md` 的关系**：那份是"底线"（做完之前必须过），这份是"反模板"（做的时候别掉进默认）。冲突处一律看 `craft-floor.md` 第八节的裁决。
- **和 `page-patterns.md` 的关系**：先有骨架，再用本节判"骨架是不是默认答案"。
- **和 `review-rubric.md` 的关系**：验收时本文第八节与 rubric 一起过；rubric 是打分表，本文是修法。
- **一次只改一层**：先结构（hero / 节奏 / 布局族），再表面（色锁 / 形状锁 / 阴影），最后文案与动效。三层一起动会互相掩盖。
