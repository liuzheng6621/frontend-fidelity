# 页面骨架库（从 0 生成时先选这个）

这份文件解决一件事：**给你一句话需求，先确定「做哪一类页面、按什么顺序摆哪些块」，再动代码。**
不先定骨架就直接写 HTML，出来的东西一定像模板——因为你在拼视觉，而不是在组织信息。

配套：`design-tokens.md`（定数字）、`component-spec.md`（定组件）、`copy-and-content.md`（定文字）、
`scripts/scaffold.mjs`（把选好的骨架真的吐成文件）。

---

## 一、选型：一句话需求 → 页面类型

| 用户说 | 页面类型 | 建议人格（见 design-tokens.md） | 骨架节 |
| --- | --- | --- | --- |
| 「做个官网/落地页，介绍我们的产品」 | 营销落地页 | editorial 或 rational | §2.1 |
| 「像 xxx.ai 那样的首页，中间能输入」 | 工具站首页 | rational（可叠 plastic 按钮） | §2.2 |
| 「做个产品文档站 / 帮助中心」 | 内容站 | editorial | §2.3 |
| 「做个后台，能看订单/用户列表」 | 管理端列表页 | rational | §2.4 |
| 「点进去看详情」 | 详情页 | rational | §2.5 |
| 「做个设置页 / 新建表单」 | 表单页 | rational 或 warm | §2.6 |
| 「要登录注册」 | 认证页 | 任一人格，但必须极简 | §2.7 |
| 「没数据的时候很丑」 | 状态页三变体 | 跟随主站 | §2.8 |

一次只做一类页面。营销页和管理端不要用同一套密度——这是最常见的「做出来怪怪的」根因。

## 二、十类骨架

每块给三件事：**最少要素**（少了就不成立）、**尺寸区间**（实测对照见 `design-evidence.md`）、**常见失败**。

### 2.1 营销落地页（单页，9 块封顶）

顺序：**导航 → Hero → 证据带 → 能力三连 → 流程/原理 → 产品截图 → 感言 → FAQ → 结尾 CTA → 页脚**

| 块 | 最少要素 | 尺寸区间（桌面 1440） | 常见失败 |
| --- | --- | --- | --- |
| 导航 | Logo + 4–6 链接 + 1 主 CTA | 高 64–88，容器 1120–1280 | 链接 8 个以上；CTA 和链接同样重量 |
| Hero | 双行标题（≤14 字/行）+ 一句副标题（≤2 行）+ 主 CTA + 一项证据（徽章/客户 logo/数字） | 高 560–900；H1 48–86 | 标题塞 30 字；塞三个 CTA；背景渐变从紫到蓝 |
| 证据带 | 3–5 个真名字的 logo，或 3 个带单位的数字 | 高 96–200 | 用灰色方块冒充 logo；数字没有单位和口径 |
| 能力三连 | 每块：图标/编号 + 4–8 字标题 + 2 行说明 | 卡高 180–260，间距 24–32 | 三张卡文案长度接近且都是抽象词 |
| 流程 | 3–4 步，每步一个动词短语 + 一句说明 | 高 400–600 | 步骤之间没有连接（箭头/线/编号） |
| 截图 | 1–3 张真截图，等宽或错落 | 高 600–1000 | 用色块当截图；截图被拉伸变形 |
| 感言 | 每人：头像 + 姓名 + 身份 + 1 段具体的话 | 卡宽 320–400 | 「很棒的产品！」这种无信息量的话 |
| FAQ | 6–8 问，手风琴，默认展开第一条 | 行高 56–64 | 12 问以上；答案写成一句话 |
| 结尾 CTA | 一句标题 + 1 个按钮 | 高 260–420 | 又铺一遍全部导航 |
| 页脚 | 3–4 列链接 + 版权 + 社媒 + 语言切换 | 高 320–650 | 列里塞 20 个链接 |

**超过 11 块就拆页。** 单页留不住注意力，也没有 SEO 结构。

### 2.2 工具站首页（带交互 Hero）

顺序：**导航 → Hero（含输入框）→ 快捷 chips → 产物画廊 → 能力三步 → 大 CTA → FAQ → 页脚**

- 输入框是本页唯一的重心：宽 680–800，`padding: 16px 20px`，圆角 12–16，**必须有 focus 态**（4px 焦点环或边框变色）。
- 输入框左下放「+ 附件」类次级动作，右下放发送按钮；发送按钮 32–40 方形，和输入框内缘对齐。
- 下方 chips 4–6 个，高 36，圆角 999 也可以（这是少数该用胶囊的地方）。
- 画廊用 6–12 张真产物缩略图；**不要 12 张构图一样的模板**，要不同形态（网页/手机/海报）。
- 常见失败：输入框无 focus；chips 点不了；画廊图没写 `width/height` 导致跳版。

### 2.3 内容站（文档/帮助中心）

顺序：**顶栏（Logo + 版本 + 搜索）→ 左侧目录树 → 正文区 → 页内目录（右）→ 上下篇**

- 三栏宽度：左 240–280 固定，正文 680–760（正文行长 >90 字符会掉可读性），右 200 可选。
- 正文结构：H1 → 一句摘要 → 代码/示例块 → 参数表 → 相关链接。
- 代码块：等宽字体、横向可滚、右上角复制按钮、**不要自动折行**。
- 锚点：H2/H3 都要带锚点链接，便于分享。
- 常见失败：正文铺满 1440 宽度；目录树不可折叠；搜索框只做装饰。

### 2.4 管理端列表页

顺序：**页头（标题 + 一句说明 + 主行动）→ 搜索/筛选 → 表格或卡片列表 → 分页 → 选中态批量操作条**

- 页头**不要包进卡片**，直接坐在页面底色上；标题 20–24/600，说明 13–14 次要色。
- 过滤区：搜索框（宽 240–320）+ 2–3 个下拉 + 「重置」；一行放不下就换行，不要横向滚。
- 表格：表头吸顶、行高 44–53、正文 13–14、数字右对齐 `tabular-nums`、操作列右固定、容器 `overflow-x:auto`。
- 分页：显示总数（「共 128 条」）+ 页码或「加载更多」，二选一。
- 选中后出现批量操作条，固定在视口底部或表格上方，**必须能清空选择**。
- 常见失败：页头塞进卡片；每行 5 个图标按钮；删除和编辑挨着；没有空状态。

### 2.5 详情页

顺序：**页头（返回 + 标题 + 状态徽标 + 主行动）→ 摘要卡（4–6 个关键字段）→ 分区（Tabs 或堆叠）→ 关联列表 → 时间线/流水**

- 页头第一行是返回入口 + 面包屑（可选），第二行标题 24/600 + 徽标 + 右侧操作。
- 摘要卡 2×3 或 3×2 网格，每格 label（12–13 次要色）在上、值（14–16）在下。
- Tabs ≤5 个；`aria-selected` 要有，键盘左右键能切。
- 时间线用左侧竖线 + 圆点 + 时间戳，最新在上。
- 常见失败：所有字段堆成 20 行的定义列表；状态只有颜色没有文字；返回按钮指向首页而不是列表。

### 2.6 表单页

顺序：**页头 → 表单分组（每组 3–7 字段）→ 粘底操作条（取消 / 保存）**

- 标签在上方，必填标记位置全页一致（推荐 `label` 后加 `*`，再在顶部说明「* 为必填」）。
- 单列表单宽 480–640；两列只在字段语义成对时用（如「起止时间」）。
- 帮助文本在输入框下方 12px，错误文案替换帮助文本的位置（不要让页面高度跳——预留一行）。
- 粘底操作条：`position: sticky; bottom: 0` + 顶部分隔线 + 半透明底。
- 常见失败：placeholder 当标签；错误只说「格式错误」；离开页面不提示有未保存内容；危险操作和保存并排。

### 2.7 认证页

顺序：**品牌标（居中）→ 标题 + 一句说明 → 表单（≤3 字段）→ 主按钮 → 次级入口（忘记密码 / 注册）→ 第三方登录（可选）**

- 卡片宽 360–420，居中，垂直居中偏上（不要正中，键盘弹出会顶飞）。
- 主按钮通栏；错误提示放在表单顶部 + 字段下方各一次（顶部给整体原因，字段给具体修法）。
- 第三方登录按钮必须有品牌规范图标，不要用文字「微信登录」加个色块。
- 常见失败：密码无「显示/隐藏」；无 loading 态（点两次重复提交）；登录失败清空已填内容。

### 2.8 状态页三变体（每个数据区都要有）

同一套布局，三种文案与行动：

| 变体 | 图标 | 标题（≤12 字） | 行动 | 禁忌 |
| --- | --- | --- | --- | --- |
| 空 | 单色线性图标 32–48 | 「还没有订单」 | 1 个主行动（「新建订单」） | 只写「暂无数据」 |
| 错 | 警示图标 + 危险色 | 「加载失败」 | 「重试」+ 展开详情 | 把 `500` 原样甩出来 |
| 无权限 | 锁图标 | 「无访问权限」 | 「申请权限」或「返回」 | 和空状态用同一套文案 |

- 容器高度 240–360，内容居中，最大宽 400，文字居中（唯一该居中的场景之一）。
- 加载态用骨架屏，**骨架要保持最终布局**（同样的行高、同样的列宽），否则一定 CLS。

### 2.9 陈列目录页（catalog：左栏目录 + 3 列图版）

给「一批彼此不同的东西」做索引：风格库、模板库、灵感库、组件陈列、案例墙。

| 块 | 最少要素 | 尺寸区间 | 常见失败 |
| --- | --- | --- | --- |
| 顶部导航 | logo + 4–6 项 + 一个主动作 | 高 60–72，固定或 sticky | 做成一整条大标题，和图版抢注意力 |
| 左栏目录 | 搜索 + 2–4 组分类（带计数） | 宽 200–240，sticky，条目高 32–36 | 一组超过 12 条还平铺（该折叠或分页） |
| 面包屑 | 2–3 级，可点 | 12–13px | 只靠颜色表示可点（必须带下划线） |
| 刊头 | 标题 + 一两句说明 + 更新信息 | 标题 40–56（衬线则 48） | 写成营销文案，而不是「收什么、谁用」 |
| 药丸筛选 | 6–12 个，当前项反白 | 高 32–36，圆角 999 | 和左栏分类表达同一件事（两套筛选必混） |
| 计数行 | 「显示 1–9 / 共 128 个」+ 排序 | 高 40 | 没有分页却给计数 |
| 图版 | 3 列（≤1080 两列，≤640 一列） | 列宽 300–460，容器锁 aspect-ratio | 每张图高度不同（版式立刻散） |
| 条目 | 图 + 标题（≤2 行）+ 一行元信息 | 图下 8–12px 起文字 | 标题不截断，列高参差 |
| 分页 / 加载 | 页码或「加载更多」，二选一 | 按钮 ≥44 | 无限滚动没有终止文案 |

**图版必须同比例**：`aspect-ratio` 写在容器上，图片 `object-fit: cover` + `object-position: 50% 0%`（截图类保留顶部）。
**卡片可以无壳**：图 + 文字直接排在底色上，靠图片边界分栏；加壳是可选的一派，不是必须。
**深阴影与无壳互斥**：选硬阴影就意味着卡片有实体边界，别再同时追求「轻盈无壳」。

骨架直接生成：`node scripts/scaffold.mjs --pages catalog`（左栏 + 药丸 + 计数行 + 3 列图版 + 分页 + 空态）。

### 2.10 电商三页（product / cart / checkout）

三页是一条链，不是三个独立页面：**详情页选出来的 SKU 必须能带到购物车行，购物车改的量必须能带到结算总额。**
拆成三个互不相干的模板，接起来一定对不上。

**2.10.1 商品详情（product）**

| 块 | 最少要素 | 尺寸区间 | 常见失败 |
| --- | --- | --- | --- |
| 图集 | 主图 + 3–6 张缩略图，缩略图是 `button` | 主图 `aspect-ratio: 4/3`；缩略图 64–72 | 缩略图做成 `<a>`（点了不换 URL，语义错） |
| 标题区 | `h1` + 一句说明 | `h1` 28–40 | `h1` 里塞型号 + 卖点 + 促销词 |
| 价格 | **三层**：主价 / 分期 / 小字注 | 主价与正文同档、只加字重 | 拼成一行字符串（改价时正则解析，必炸） |
| SKU 组一（颜色） | 36×36 圆点 + `aria-label` | `border: 2px solid transparent`，选中换实色 | 显示颜色名文字（占宽，且 5 个以上排不下） |
| SKU 组二（规格） | 文字按钮，可带 `+800` 增量 | 高 40，选中内描边 | 两组用同一种形状（用户分不清两组选择） |
| 数量 | 步进器，钳 1–99 | 按钮 ≥44，输入宽 48–56 | 只有输入框没有步进（移动端难输入） |
| 主 CTA | 加购 + 立即购买 | 高 44，`r8` | 只给「立即购买」，没有加购 |
| 参数表 | 5–8 行，`th[scope=row]` | 行高 40–48 | 用 `div` 拼表（读屏读不出行列关系） |

价格三层不要写成一行：`.price-main`（主价）/ `.price-inst`（分期）/ `.price-note`（小字注）。
主价**不放大**、只加 600 字重是 Apple 一派；国内电商惯例是 24–32px 红字——**选一派，别混**。

**2.10.2 购物车（cart）**

| 块 | 最少要素 | 尺寸区间 | 常见失败 |
| --- | --- | --- | --- |
| 页头 | `h1` + 「共 N 件」+ 继续购物 | 高 56–72 | 把件数写成静态文案 |
| 行项目 | 图 / 名 + SKU / 步进 / 单价 / 小计 / 删除 | 行高 96–112 | 5 列写成 4 列，删除按钮掉到第二行 |
| 汇总卡 | 小计 / 运费 / 优惠 / 应付 | 宽 320–360，sticky | 只在结算页给总额（购物车看不到钱） |
| 优惠码 | 输入 + 使用 + 结果提示 | 输入高 40 | 前端校验通过就当真（必须服务端再校验） |
| 空态 | 图 + 一句 + 去逛逛 | 居中，`min-height` 240 | 空车时重定向到首页（用户不知道为什么被弹走） |

**单价用弱色、小计用强色**：两者在数量为 1 时数值相同，颜色不分层会看起来像重复渲染。

**2.10.3 结算（checkout）**

| 块 | 最少要素 | 尺寸区间 | 常见失败 |
| --- | --- | --- | --- |
| 步骤条 | 3 步，当前步 `aria-current="step"` | 圆标 22，行高 32 | 用进度条假装步骤（看不出还差几步） |
| 地址表单 | 收货人 / 手机 / 详细地址必填 | 输入高 40 | 只标 `*` 不写错误文案 |
| 配送方式 | 2–3 个单选，带价格 | 行高 ≥44 | 运费改了总额不跟着变 |
| 支付方式 | 2–3 个单选 | 行高 ≥44 | 和配送方式用同一组 `name` |
| 订单摘要 | 行项目缩略 + 金额 + 应付 | 宽 340–360，sticky | 摘要里没有行项目，只有总额 |
| 提交栏 | 提示 + 返回 + 提交 | sticky `bottom: 0`，**必须不透明** | 半透明底栏让下面选项透出来，像重影 |

步骤条圆底用 `--brand-fill` 而不是 `--brand`：浅色品牌色配白字在暖色人格下只有 1.68:1。

骨架直接生成：

```bash
node scripts/scaffold.mjs --persona warm --pages product,cart,checkout --verify
node scripts/flow.mjs --flow scripts/flow.commerce.example.json --base <本地服务>
```

`flow.commerce.example.json` 是 42 步的完整链路：换色 → 换容量（主价按增量重算）→ 改数量 →
加购（只改角标不跳页）→ 购物车改量 → 删行 → 优惠码 → 空态 → 结算必填校验 → 运费联动。

## 三、移动端（390 宽）骨架差异

- 导航：汉堡 + 品牌标；抽屉从右侧滑出，带遮罩，Esc/点遮罩关闭。
- 底部 tab 4–5 个，高 48–56 + `env(safe-area-inset-bottom)`；**只有一级导航能进 tab**。
- 主 CTA 粘底通栏（高 48–52），距底部留 12–16 + 安全区。
- 表格改卡片：每行一张卡，字段 label 在左（次要色，宽 72–96），值在右，`grid-template-columns: 96px 1fr`。
- 列表项高度 ≥56（触控），图标按钮容器 ≥44×44（图标本身可以 20）。
- 弹窗改底部抽屉（`align-items: end`），不要居中弹窗——小屏会撞键盘。

## 四、内容最低量（避免「占位感」）

生成阶段的文案只允许两类：**真实信息** 或 **明确标注的占位**。禁止第三种（看起来像真的其实是废话）。

- 营销页：至少 1 个真数字（带口径）、1 个真名字（客户/作者）、1 张真截图。
- 后台：至少 3 行结构真实的数据（不是 `foo`/`bar`/`lorem`），1 个非空状态 + 1 个空状态。
- 占位统一写成 `{{TODO: 一句话说明要什么}}`，交付前一跑 `grep -rn "{{TODO"` 就知道还差多少。
- 三段长度相近、句式相同的假文案是最强的 AI 信号——宁可只写两段。

## 五、先出区块清单，再写代码

动手前在文件顶部写 5–15 行注释即可：

```

01 nav       · logo / 4 链接 / CTA

03 evidence  · 3 数字（口径写在旁边）
04 features  · 3 张卡（不等长文案）
05 flow      · 3 步

```

`scaffold.mjs` 生成的文件开头就带这段注释，改的时候照着删/加块。

## 六、自查（生成完先过这 10 条）

1. 每个区块都能用一句话说清它解决什么问题吗？说不清就删。
2. 页面上有几个主行动？>1 就错。
3. 有没有两个区块在讲同一件事？
4. 最长的那个段落几行？>5 行拆成列表。
5. 空/载/错三态是否都有，且布局不跳？
6. 390 宽有没有横向滚动？有没有触控目标 <44？
7. 键盘 Tab 能不能走完，焦点是否可见？
8. 所有数字是否右对齐 + 等宽数字？
9. 有没有出现三种以上圆角、三种以上阴影？
10. 删掉所有装饰（渐变、插画、动效）后，页面还站得住吗？
