# 站酷 ZCOOL：UI 频道「头版」的排版法

单站实测（2026-10-25，Edge 131 + playwright-core，1440×900 采集）。
采样地址 `https://www.zcool.com.cn/discover/17` —— 即「UI」分类的默认落地页
（`<title>UI设计素材_UI设计作品,海报,作品集欣赏下载-站酷ZCOOL</title>`）。

> **采集边界**：这个站有阿里云 WAF 滑块，**headless 浏览器一律被拦**（返回「滑动验证页面」），
> 必须以 `headless: false` 的真实 Edge 窗口访问；即使如此，页面加载 5–8 秒后仍会弹出验证浮层，
> 需要在 `evaluate` 里移除 `#waf_nc_block` / `.waf-nc-mask` 才能截图与量取。
> 实测数据是浮层出现**之前**那份已渲染完整的 DOM，可信。

## 一、它是什么气质

> **一张报头 + 一片等宽的图版：版面归版面，作品归作品。**

四个可辨识特征：

1. **零装饰**。卡片没有背景、没有圆角、没有阴影，图就是边界。全站阴影出现次数屈指可数（`0 8px 32px` 4 次，全是浮层），
   分隔线只有一条 `0.8px solid #ededed`。
2. **等宽网格，不做瀑布**。4 列 × 283px、列距 24px、行距 300px，缩略图强制 4:3（`520×390` 原图 → `283×212` 显示，
   `object-fit: cover`）。一屏 8 张，四行下来网格纹丝不动。
3. **橙色只给两个地方**。`#FF5E3B` 只出现在「注册」和「关注 UI」，其余全是黑灰白。
4. **信息全部落在文字行**。标题 14/400、作者行（20px 圆头像 + 名字）、右下角火苗数 12px。
   图上不压任何文字，只有一个 hover 才出现的浅色渐变遮罩 + 一个 32px 圆形图标。

它和 wegic（黑舞台上的一件塑料制品）、即时设计（浅灰蓝底板上的一叠彩色纸卡）刚好构成三极：
**这两个都在「卖一件事」，站酷在「陈列一堆东西」**。

## 二、令牌表（实测）

### 颜色

| 角色 | 值 | 用在哪 |
|------|-----|--------|
| 主文字 | `#282828`（`rgba(0,0,0,.9)`，该值出现 38 次） | 标题、频道名、正文 |
| 次文字 | `#555555` | 分页未选中、底部条文字 |
| 弱文字 | `#888888` | 作者名、推荐数、副标题、图标色 |
| 提示文字 | `#999999` | 占位符、更弱的元信息 |
| 深字 | `#191919` / `#1f1f1f` / `#222222` | 登录、下拉、选中胶囊 |
| 背景 | `#FFFFFF` | 全局 |
| 浅底 | `#F2F2F2` | 未选中胶囊 |
| 选中胶囊 | `#222222` | 黑底白字 |
| 分隔线 | `#EDEDED`（`0.8px`）/ `#E5E5E5`（描边 `0.8px`） | tab 行底、下拉框、圆图标钮 |
| 品牌橙 | `#FF5E3B` | 只给「注册」「关注 UI」 |
| 火苗色 | 橙色 SVG | 卡片右下角推荐标记 |

**要点**：`0.8px` 是这个站的固定发丝宽度（不是 1px）。它比 1px 更软，四角不显笨。

### 圆角分工（实测频次：`50%` 136 → `12px` 60 → `24px` 60 → `8px` 43 → `16px` 16）

| 值 | 归属 |
|----|------|
| `50%` | 头像（20px）、圆形图标钮（44px）、回到顶部 |
| `24px` | 大圆图标底板 |
| `16px` | **胶囊**（高 31，`padding: 6px 16px`） |
| `12px` | 中号容器/图片块 |
| `10px` | 顶栏按钮（注册/登录，76×36） |
| `8px` | 下拉框（32 高，`0.8px` 描边） |
| `4px` | 小标记 |

**注意它没有「一处圆角」**：从 4 到 24 每一档都有归属，胶囊 16 而不是 `999px` —— 全圆胶囊在这套体系里会显得过于软，
16px 的胶囊看起来仍是胶囊，但四角有硬度。**这是个可直接抄的细节**。

## 三、字阶（实测：全站只有 4 个字号）

| 字号 | 字重 | 行高 | 出现次数 | 用途 |
|------|------|------|----------|------|
| `40px` | 700 | `44px`（1.10） | 1 | 频道名（h1「UI」） |
| `16px` | 400/500 | — | 16 | 主分类 tab 文字（注意：tab 用 16px，比正文大） |
| `14px` | 400/500 | `normal` | **934** | 一切正文：卡片标题、作者、下拉、按钮、分页、占位符 |
| `12px` | 400 | — | 153 | 推荐数、底部条、副标题 |
| `10px` | — | — | 1 | 极端小标 |

**这站几乎没有字阶**。40 只用于频道名，然后直接掉到 16/14/12。
**层级靠字号间距 40→16→14→12 实现的不是「8 档」，而是四档 + 一处强对比**。
它对的地方是：正文 14 在中文内容站属于可用的下限；错的地方见第六节。

### 字体

```
font-family: "PingFang SC", "Lantinghei SC", "Microsoft YaHei", "HanHei SC",
             "Helvetica Neue", "Open Sans", Arial, "Hiragino Sans GB", 微软雅黑,
             STHeiti, "WenQuanYi Micro Hei", SimSun, sans-serif;
```

- **零 webfont**（`document.fonts.size === 5`，全是系统栈 + 一个图标的 iconfont）。
- 但注意有个 `HYWenHei-GEW` 排在栈尾 —— 装了汉仪文黑**才会**用到，没装就落到系统的 PingFang/雅黑。
  这种「品牌字体放在栈尾、不下载」的做法，对**中文站**是省钱且不崩的选择：字形统一靠系统。
- 结论：中文内容站**不必为正文下载字库**，需要品牌感时把展示字体挂在 h1/频道名上即可。

## 四、版式节奏

```
56   顶栏（白）
120  活动 banner（通栏，可轮播）
56   主分类 tab（15 个）+ 0.8px 分隔线
67   子分类胶囊（11 个）
301  频道头（h1 40/700 + 一句副标题 + 关注钮 + 4 个 44px 圆图标钮）
32   工具行（左「编辑精选/最新推荐」，右「附件/视频/城市/学校」）
     图墙：4 列 × 283，列距 24，行距 300（60 张 = 15 行）
40   分页
32   固定底条（备案/版权/帮助）
```

三条值得学的：

1. **两级分类，一级是横排文字 + 一行下划线，二级是胶囊**。
   一级（15 个品类）用文字 tab 是因为它**长期不变**，二级用胶囊是因为它**会随品类变**。
   两套控件形状不同，用户扫一眼就知道哪个管得更大。
2. **频道头是「一屏之内唯一的居中块」**。整页只有 h1/副标题/关注键居中，其余全部左对齐网格 —— 眼睛先落在中间，再顺着左边线扫图。
3. **工具行贴着图墙走**：排序与筛选在图墙上方 32px 处，和内容没有多余留白，用户改筛选条件时视线不离开图片。

## 五、组件配方

### 卡片（这是全站唯一重要的组件）

```html
<div class="content-box_card_item">        <!-- 283 × 264 -->
  <a class="cardCover cardGradient">        <!-- 283 × 212，无圆角无阴影 -->
    <img class="cover-img">                 <!-- object-fit: cover，4:3 -->
    <div class="image-mask"></div>          <!-- 默认 height: 0，hover 展开 -->
  </a>
  <div class="cardStatus">                  <!-- 绝对定位，右下角 32×24 -->
    <svg width="13" height="13">火苗</svg>
  </div>
  <div class="cardTitle-warp" style="margin-top:8px">   <!-- flex 行 -->
    <a class="cardTitleBox"><span class="cardTitle">标题</span></a>  <!-- 14/400，单行 ellipsis -->
    <div class="cardStatistics">            <!-- 右对齐 -->
      <svg width="16" height="16" color="#888888">赞</svg>
      <span size="12">23</span>             <!-- 12px #888 -->
    </div>
  </div>
  <div class="cardUserInfo">                <!-- 20px -->
    <img class="avatar">                    <!-- 20×20，border-radius: 50% -->
    <span>轻妙设计</span>                    <!-- 14px -->
  </div>
</div>
```

**三个关键数字**：

- `margin-top: 8px` 把标题和图的间距压到很小 —— 图和标题是一件事，不是两张卡。
- 标题**单行**、`ellipsis`，19px 高固定。标题长度差异被吃掉，网格才不会参差。
- 作者行 20px 高、头像 20px —— 头像和文字同一行高，视觉上是一条细线。

### 顶栏按钮

| 元素 | 实测 |
|------|------|
| 注册 | `76 × 36`，`#FF5E3B`，白字 `14px/500`，`border-radius: 10px`，`padding: 2px 12px` |
| 登录 | 同尺寸，透明底，`#191919`、`14px/400` |
| 搜索框 | 外框 `461 × 32`，占位符 `14px`，无边框（靠底色/描边，实测该层透明，视觉上是浅灰底） |

按钮 `14/500` + `radius 10` + 高 36 —— 比正文只重一档，不靠字号靠色调拿注意力。

### 分类条

| 元素 | 实测 |
|------|------|
| 主分类 tab | `h2` 高 56、`padding: 0 24px`、`16px`、选中 `#222` |
| 主分类选中标记 | 下方一条短横线（约 28×2–3px，深色；DOM 里是伪元素/独立滑块，非 `border-bottom`） |
| 子分类胶囊 | 高 31.2、`padding: 6px 16px`、`border-radius: 16px`、`14px`；选中 `#222` 底白字，未选 `#F2F2F2` 底 `#222` 字 |
| 胶囊行容器 | `padding: 20px 20px 0` |

**胶囊高度 31 而 tab 是 56** —— 两级控件的物理高度差就是层级差，比颜色差更可靠。

### 下拉筛选（工具行）

`112–128 × 32`，白底、`0.8px solid #E5E5E5`、`radius 8`、`14px #333`，右侧一个 `⌄`。
左侧「编辑精选 / 最新推荐」是**排序**，右侧「附件 / 视频 / 城市 / 学校」是**筛选**，形状一样但分居两端 —— 位置区分语义。

### 分页

`40 × 38`，`radius 0`（**直角**），选中黑底白字，其余 `#555`；`1 2 3 4 5 6 7 … 99 100 ›`。
直角分页在这个全站圆角的体系里是**唯一的直角**，反而是个记忆点：它标记「这是导航，不是内容」。

## 六、它自己没做好的七处

照例，这些**不要抄**：

1. **移动端零适配**。`meta viewport` 有，但 390 宽下 `document.scrollWidth = 1200`，
   卡片仍从 x=30 铺到 x=1147，用户只能横向滚。和有同样问题的 UI 世界是一对。
2. **顶栏没有固定**（`position: relative`）。滚到第 5 行想换分类要回到顶部，而图墙有 15 行。
3. **hover 反馈极弱**：`image-mask` 默认 `height: 0`，hover 只展开一层浅渐变 + 一个圆形图标，
   图本身不缩放不变亮。鼠标停在图上，几乎看不出「已选中」。
4. **标题单行截断 + 没有 `title` 提示的全部卡片**：部分卡片 `<a>` 上有 `title` 属性，标题本身被 `ellipsis` 截断后，
   触屏/键盘用户没有途径看到全名。
5. **频道头占了 301px**：一屏 900 里，顶栏 + banner + 两级分类 + 频道头就吃掉 660px，
   图墙在首屏只剩 1.5 行。**它自己卖的内容被头部的仪式感挤下去了。**
6. **`0.8px` 描边在高 DPI 下会虚**（1.6 物理像素 → 浏览器四舍五入成 1 或 2，不同元素表现不一致）。
   要软就用 `#EDEDED` 的 1px，要就用 1px；`0.8px` 只在恰好 1x 屏成立。
7. **banner 是 1265 宽通栏、内容容器是 1205**：两者左边界差 30px，滚动时视觉上会「错一下」。

## 七、能搬什么 / 不能搬什么

| 结论 | 依据 |
|------|------|
| ✅ **两级分类用形状区分**（文字 tab vs 胶囊），并让物理高度不同（56 vs 31） | 实测，且它自己一致 |
| ✅ **卡片不画壳 + 图强制 4:3 + 标题单行 + 8px 间距** | 4 列网格 60 张不错位 |
| ✅ **圆角每档都有归属**（4/8/10/12/16/24/50%），胶囊用 16 而非 999 | 频次统计 |
| ✅ **橙色只给主行动**（注册、关注），其余不留彩色 | 整页仅两处高饱和 |
| ✅ **`0.8px` 发丝线的思路**（比 1px 软） | 但落地时换成 1px + 更浅的颜色更稳 |
| ✅ **直角分页**做「导航 vs 内容」的形状区分 | 全站唯一直角，反而清晰 |
| ❌ **移动端不重排** | 390 下 1200 宽横向滚 |
| ❌ **顶栏不 fixed** | 15 行长列表 |
| ❌ **hover 只加一层浅遮罩** | 触屏无所谓，鼠标端等于无反馈 |
| ❌ **频道头吃 660px** | 内容被挤到首屏以下 |
| ❌ **`0.8px` 直接落地** | 高 DPI 下不稳定 |
| ❌ **整站只有四档字号**（40/16/14/12） | 少并不等于清楚：14 同时承担标题、正文、按钮、分页，只能靠色阶区分；需要更多层级时必然加字号 |

**混合口径**（做内容站/后台混合产品时）：
底色用 `#FFFFFF` + `#F2F2F2` 做浅底；文字三档 `#282828 / #555 / #888`（**不要 `#7f7f7f`，3.9:1 不合格**，
`#888` on white = 3.5:1 也不合格，见下）；分隔线用 `#EDEDED` 1px；主行动色单一且高饱和；
圆角 8/12/16 三档 + `50%` 头像；阴影只给浮层。

> **对比度实测（本仓 `contrast_check.py`）**：`#888888` on `#FFFFFF` = **3.54:1**，不满足 4.5:1。
> 站酷用它做作者名与推荐数（12px 小字），这是**内容站最常见的可读性债**。
> 抄的时候把 `#888` 换成 `#6B6B6B`（4.9:1）或给到 14px；`#999`（2.85:1）只能做分隔性文字。

## 八、复现清单（10 条）

1. 内容宽 **1205**（1440 视口下左右 30），**4 列 × 283 + 24px 列距 + 36px 行距（块高 300）**；
   栏宽用 `repeat(4, minmax(0, 1fr))` + `gap: 24px`，别写死 283。
2. 缩略图 **`aspect-ratio: 4 / 3`** + `object-fit: cover`，`border-radius: 0`、无背景无阴影无 padding。
3. 标题 **14px / 400 / 单行 ellipsis / `margin-top: 8px`**，行高固定 19–20px。
4. 计数行在标题右侧**右对齐**，图标 16px + 数字 12px；颜色改 `#6B6B6B`。
5. 作者行 **20px 高**（头像 20 圆 + 名字 14），与标题间距 4–6px。
6. 一级分类：**文字 tab 16px / 行高 56px / padding 0 24px / 底部 3px 短下划线**；行底 1px `#EDEDED`。
7. 二级分类：**胶囊高 31 / padding 6 16 / radius 16**；选中 `#222` 底白字，未选 `#F2F2F2` 底 `#222` 字。
8. 顶栏 **56px、白底、无阴影**；主行动按钮 `radius 10 / 高 36 / 14px 500 / 品牌橙`，只此一处彩色。
9. 分页 **40×38 直角**，选中黑底白字；右侧配「回到顶部」圆形浮动钮。
10. 移动端：**≤1080px 三列、≤760px 两列**，并保住 `scrollWidth === innerWidth`；
    顶栏在长列表里改 `position: sticky; top: 0`（它没做，你要做）。

## 十、重采方法

**必须先知道的三件事**：

1. **headless 一定被拦**。`probe-ref.mjs` 默认 `headless: true`，对本站返回的是「滑动验证页面」（16 个元素、
   标题里有「访问验证」）。用 `--headed` 或自己起脚本传 `headless: false`（窗口可以 `--window-position=-2400,-2400` 挪出屏幕）。
2. **加载 5–8 秒后会弹验证浮层**，它会在截图里盖住内容，并且 `hover` 会被 `.waf-nc-mask` 拦截。
   在量取与截图前执行：

   ```js
   await page.evaluate(() => {
     for (const s of ['#waf_nc_block', '[class*=waf]', '[id*=waf]', '[class*=captcha]'])
       document.querySelectorAll(s).forEach(e => e.remove())
   })
   ```

3. **浮层出现之前 DOM 已完整渲染**，所以数据本身不受影响；只是要抓紧在浮层出现前（或移除后）截图。

```js
const ctx = await chromium.launch({
  executablePath: '<edge>', headless: false, viewport: { width: 1440, height: 900 },
  userAgent: '<真实 UA，带 Edg/131>', locale: 'zh-CN',
  args: ['--disable-blink-features=AutomationControlled', '--window-position=-2400,-2400'],
})
```

量什么：卡片用 `a[href*="/work/"]` 定位后取 `parentElement`（`.content-box_card_item`）看 283×264；
图墙的列距看相邻卡片 `getBoundingClientRect().left` 差值（24）；行距看 `top` 差值（300）；
字号频次遍历叶子元素的 `fontSize`；圆角频次同理。移动端判定只要一句：
`document.documentElement.scrollWidth === window.innerWidth`（本站为 1200 ≠ 390，判定失败）。
