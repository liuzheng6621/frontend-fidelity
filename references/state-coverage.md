# 状态覆盖（state coverage）

> 判据来源：OpenDesign `craft/state-coverage.md`（Apache-2.0）蒸馏 + WCAG 2.2 / NN/g / Material 3 /
> Apple HIG / Baymard 结算研究。**只取判据与数字，不复制原文**；中文口径按本站语料重写。
> 这份文件管「哪些状态必须存在、每个状态必须装什么」；长什么样由 `design-tokens.md` / `visual-system.md` 决定。

## 一、五态铁律

任何**取数据 / 转数据 / 收数据**的界面，五个状态全都要能截出图。只做「有数据」那一版是 AI 生成界面
最稳定的失败模式——不是之一。

| 状态 | 什么时候出现 | 必须装什么 |
| --- | --- | --- |
| **加载** | 数据在飞 | 骨架屏 / spinner / 壳；**外加 15 秒「比预期久」兜底** |
| **空** | 还没记录，或查询返回空 | 标题 + 一句白话解释 + 主 CTA |
| **错误** | 请求失败、服务端错、校验拒绝 | 白话原因 + 恢复动作 + **保留用户已填内容** |
| **有数据** | 主路径 | 设计稿真正画的那一版 |
| **边界** | 超量、超长、缺可选字段、RTL / 长单词、半断网 | 布局不塌 |

**验收方式**：列表、表格、卡片、表单、面板，逐个渲染并截图。缺态直接算没做完——
`node scripts/scaffold.mjs --pages states` 生成的就是这一套，别自己另起一套。

## 二、边界矩阵（按页面类型）

光有「空态」不算，边界要具体到能造出来的数据。

| 页面类型 | 必须扛住的边界 |
| --- | --- |
| 后台 / 表格 | 1 万行以上、全数字列、排序 + 筛选同时生效 |
| 移动卡片 / 列表 | 200 字标题、头像缺失、次要 CTA 缺失 |
| 表单 | 所有可选字段为空、所有必填字段顶到最大长度 |
| 搜索结果 | 单字符查询、只有特殊字符的查询、1000+ 结果 |
| 详情页 | 所有可选元数据缺失、主内容 RTL 夹 LTR 片段 |

## 三、表单比别处多三态

| 状态 | 触发 | 行为 |
| --- | --- | --- |
| **未触碰** | 还没获得过焦点 | 默认样式，不出任何校验文案 |
| **已填且合法** | 用户输入过且通过 | 保留常驻帮助文案；**不要变绿**（绿色成功态是噪音） |
| **提交中** | 点了提交、等响应 | 提交按钮进 loading，字段锁住防重复提交 |

校验时机只有一条：**失焦（blur）才校验，不是第一次按键**。密码这类实时字段，也是
「第一次失焦之后」才逐键校验。输入一变合法，错误文案**立刻消失**，不要等下一次失焦。
细节见 `form-rules.md`。

## 四、空态是独立状态，不是「什么都没有」

| 类型 | 构成 |
| --- | --- |
| **首次使用** | 插画 + 标题 + 价值句 + 主 CTA。空态就是上手引导那一刻 |
| **无结果** | 复述查询词 + 给替代方向，绝不能是纯白 |
| **清空后** | 轻松语气（"都处理完了"）+ 可选下一步 |
| **错误伪装成空** | **禁止**。错误是独立状态，必须带恢复信息 |

服务端能返回兜底内容（推荐、相关分类、热门）时优先用服务端——它比你更懂「没搜到，但也许该试 X」。

## 五、错误态要回答三件事（按顺序）

1. **发生了什么**——「你的卡被拒了」，不是「出错了」。
2. **为什么（能知道的话）**——「余额不足」/「网络不可达，检查连接」。
3. **用户能做什么**——重试按钮、替代路径、或客服入口。

**用户输入必须跨错误保留**。提交失败表单被清空是直接的流失原因。

### 五级严重度，按范围配

| 级别 | 表现 |
| --- | --- |
| 字段级 | 红框 + 行内文案，焦点移到该字段 |
| 表单级 | 顶部错误摘要条 + 各字段标记 |
| 区块级 | 区块内嵌面板 + 重试，周围区块照常可用 |
| 页面级 | 整页错误态 + 插画 + 恢复 CTA |
| 应用级 | 常驻横幅或模态（功能性丧失才用） |

一个字段校验失败，不配用页面级错误。

### 重试纪律

- 第一次点击立刻重试。
- 第二、三次退避：2s → 4s → 8s 封顶。
- 三次失败后把「重试」换成「联系客服」+ 可复制的错误 ID。用户该做的都做了，该上人了。
- 第一次重试之后，错误面板上要显示「上次尝试：Xs 前」，让用户知道这个失败有多旧。

## 六、加载指示器按时长选，不按组件库有什么选

| 期望时长 | 指示器 |
| --- | --- |
| 0–300ms | 不给。同步渲染，用户感知不到延迟 |
| 300ms–2s | 轻量 spinner 或骨架 |
| 2–10s | 与布局匹配的骨架，或带标签的 spinner（「正在加载付款信息…」） |
| 10–30s | 确定进度条 + 可取消 |
| 30–60s | 进度条 + 明确的取消入口（15s 的「比预期久」已经提示过，不要重复） |
| 60s+ | **停掉动画**，给错误 + 重试 / 取消 / 继续 |

**永远不要留一个无限转的 spinner**。每个请求起一个超时。

## 七、状态变化必须被朗读，焦点必须被安置

| 变化 | ARIA | 焦点动作 |
| --- | --- | --- |
| 提交后的行内错误 | 消息上加 `role="alert"` | 移到第一个出错字段 |
| Toast / 非紧急确认 | `role="status"`（polite） | 不动焦点 |
| 严重错误 / 破坏性确认 | `role="alertdialog"`（assertive） | 移到对话框 |
| 开始加载 | `role="status"` 播报（「正在加载…」） | **不要**把焦点丢给 spinner |
| 加载结束、内容出现 | — | 若由用户动作触发，焦点移到加载出的内容 |

live region 容器必须在内容注入**之前**就存在于 DOM 里。`aria-live` 和内容同时插入不会触发播报。

## 八、常见错误（逐条可查）

- 只渲染「有数据」态，加载 / 空 / 错误 / 边界全缺。
- 空态就是一个空白或「暂无数据」四个字，没有标题、没有解释、没有动作。
- 错误文案写「出错了」，没有原因也没有恢复路径。
- spinner 没有超时，慢请求或失败请求就无限转。
- 校验失败把表单清空，逼用户重填。
- 行内校验在第一次按键就开火。
- 只有一个区块在取数，却整页替换成 loading（骨架盖住了整个 chrome）。
- 同一个页面里 toast 从不同位置冒出来。
- 只用颜色表达错误，没有图标也没有文字。
- 会自动消失的 toast 悬停或聚焦时不能暂停（WCAG 2.2.1）。

## 九、怎么接进脚本

```bash
# 生成五态页面（含空 / 载 / 错 / 边界）
node scripts/scaffold.mjs --persona rational --out ui --pages app,form,states --verify

# 审计：空 alt / 对比度 / 可聚焦元素 / 焦点可见
node scripts/audit.mjs --url http://localhost:5173/ --themes light,dark
```

`audit.mjs --red-flags` 能机械判一部分（无 alt、对比度、焦点样式缺失），
但**状态是否真的存在**只能靠截图对——把五态截图放进 `.design/`，缺一张就是没做完。
