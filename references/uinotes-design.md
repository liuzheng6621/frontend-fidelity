# UI Notes（uinotes.com）设计蒸馏

采集自 <https://uinotes.com/> —— 真实产品 UI 截图灵感库（477 个应用 / 180,158 张截图）。桌面 1440 + 移动 390 实测，2026-10-30。

它是本参考库里的第六个单站样本，也是第三个「内容陈列站」，但陈列方式又是新的：**不画壳，把别人的真机截图当墙纸铺开**。

---

## 一 气质：一间只挂样片的美术馆

一句话：**没有说明牌，只有一排排真机截图。**

四条一眼能认出来的特征：

1. **截图是主体，界面是给截图让路的。** 没有卡片壳、没有边框、没有阴影，3 列 × 2 张截图直接铺在白底上；第三张超出列宽就被裁掉，只露出 1.8 张。
2. **数字当标题。** `477 个应用 180158 张截图` 用 48px，数字是靛蓝 `#446BF8`；说明文字退成 18px 灰。全站最大的字不是口号，是**数量**。
3. **两套色系并存。** 主体冷灰蓝（`#24272e` / `#8e919e` / `#f1f2f4`），顶部促销条暖琥珀（`#5c564f` / `#f5f2eb`）——分属两组令牌，促销条像贴在画框上的一张便条。
4. **移动端不重排。** viewport 把宽度锁在 1420，390 的屏上整站等比缩到 27%，正文物理高度约 3.5px。

## 四 版式节奏

| 段 | 高度 | 备注 |
| --- | --- | --- |
| 促销条 | 56 | 白底 + 1px `#f5f2eb` 下边 |
| header | 72 | `sticky`，`top: 56`，透明渐变底，无边框无阴影 |
| hero | 680（128 → 808） | 渐变段；大数字 y=192、说明 y=274 |
| 图标墙 | 3 × 110 | y=390 / 516 / 642，图标 80 + 间隙 30 |
| 筛选条 | 56 | 底部 1px `#f1f2f4` |
| 网格 | 起点 896 | 容器 1376（左右 32），3 列 440，列距 28 |
| app 条目 | 626 | 图标行 ≈92 + 截图带 520 |
| 行距 | ≈40 | 估算自截图，未逐像素量 |
| 末尾 | 「没有更多了~」 | 无限滚动的终点，无页脚 |

三条值得学的：

1. **数字放在标题位。** 48px 不是口号，是统计。想让落地页「看起来有货」，把真实数量放成最大的字，比写形容词管用。
2. **全站只有一个正方形尺寸 80。** 图标墙的图标和 app 图标都是 80×80（`border-radius: 24px`），两处的视觉重量因此完全一致。
3. **留白全给图片。** 容器只留 32，但列距 28、行距 40 都让给截图；文字区压到 92px 内解决图标 + 名称 + 副标。

## 五 组件配方

### 5.1 app 条目（440 宽，626 高）

```html
<article class="app" style="width:440px">
  <div class="app__head">
    <span class="app__icon"></span>            <!-- 80×80 r24 -->
    <div class="app__meta">
      <h3 class="app__name">DtdSounds</h3>     <!-- 20/500 #282c3d -->
      <p class="app__tag">睡眠白噪音</p>        <!-- 13/400 #8e919e -->
    </div>
    <div class="app__stats">                   <!-- 右对齐纵排，间隔 8 -->
      <span class="pill">v2.5 - 2026.09</span> <!-- 107×32 -->
      <span class="pill">74 张截图</span>       <!-- 81×32 -->
    </div>
  </div>
  <div class="app__shots">                     <!-- 裁切容器，overflow:hidden -->
    <div class="shot"></div>                   <!-- 240×520 r16，一套 5 个，gap 12 -->
  </div>
</article>
```

- 图标右缘到名称左缘 12px；名称到副标 25px（名称盒高 23、副标盒高 17）。
- 两枚胶囊是 `flex-direction: column; align-items: flex-end`，宽度由文字撑开（107 / 81 都是内容宽度），不是固定值。
- **截图带是裁切的**：5 个 240 宽的槽排成一行（总宽 1248），外层只有 440 宽，所以看到 1.8 张。没有 hover 提示、没有「查看全部」，只能点进去。

### 5.2 信息胶囊

- 高 32、`padding: 0 12px`、`border-radius: 6px`、`background: #f8f8f8`、字 13/400 `#666`。
- 注意它不是胶囊圆角（16/999），是 6px 小方角——和截图槽的 16px 形成两级。

### 5.3 应用图标

- 80×80、`border-radius: 24px`、占位底 `rgba(0,0,0,.024)`（图未加载时是一块极淡的灰）。
- 图标墙与 app 条目共用同一套 80/r24，只是墙里的图标没有文字。

### 5.4 截图槽与截图带

- 槽 240×520（≈9:19.5）、`border-radius: 16px`、`overflow: hidden`。
- 截图用 `object-fit: fill`（不做比例裁切，宁可轻微变形，保证整屏可见）。
- 每 app 5 张，`gap: 12`。
- **「uinotes.com」水印烧在图片像素里**，不是 DOM 叠层也不是 `::after`（`.sample::after { content: none }`，全站找不到含该文字的节点）。

### 5.5 搜索框

- 520×48、`border-radius: 4px`、白底无边框（靠底色与 header 渐变区分）、15px、占位「搜索截图和App...」。
- 放大镜图标内嵌在框的右侧，点击区域与输入区重叠但视觉上是一体的。

### 5.6 登录 / 注册

- 100×40、`border-radius: 20px`（=半高，全圆）、bg `#24272e`、白字 14/400。
- 全站唯一的高对比实心按钮出现在 header 右上角——因为主体是要给截图让路的。

### 5.7 促销条

- 56 高、白底、1px `#f5f2eb` 下边、13px `#5c564f`。
- 右侧「了解详情」75×23、`border-radius: 2px`、11/600、bg `#24272e` —— 全站最小的按钮，但颜色最重。
- 带 × 关闭。

### 5.8 筛选条

- 56 高、底部 1px `#f1f2f4`。
- 左：「公司：全部 ▾」「行业：全部 ▾」14/400 `#666`。
- 右：「共 477 个应用」14/400 `#8e919e` —— 计数放右边，和左边的下拉形成一条安静的横线。

### 5.9 无限滚动的尾巴

- 加载中：「加载中...」14/400 `#8e919e`，居中。
- 到底：「没有更多了~」14/400 `#8e919e`，居中。
- 没有分页、没有页码、没有回到顶部。

## 六 七处没做好（别学）

1. **移动端整体缩小。** viewport 锁 1420，390 的屏上正文物理高度约 3.5px，等于不可读。这是「有 viewport meta 但仍然没适配」的隐蔽版本——比横向溢出更糟，因为表面上不横向滚动。
2. **没有 h1。** `h1`/`h2`/`p` 语义全空，最大的字是一个 `div`。读屏和 SEO 都拿不到大纲。
3. **长列表没有出口。** 无限滚动到底才说「没有更多了~」；没有分页、没有锚点、没有「跳到底部」。
4. **没有页脚。** 全站只剩一个 `box: 0` 的隐藏「关于」链接，没有备案号、隐私政策、联系方式。
5. **两套色系并排。** 暖琥珀促销条与冷灰蓝主体互不相干，也不共享圆角与字重规则，像是两个团队各贴一块。
6. **截图裁成 1.8 张，且没有「还有 3 张」的提示。** hover 也没有任何反馈（全站 0 阴影、1 个动效），用户只能盲点。
7. **水印烧进像素。** 想裁剪或批量取图只能自己动手，而且水印正压在最上方的状态栏区域——恰好是截图里信息密度最高的位置。

## 七 能搬什么 / 不能搬什么

| 做法 | 能搬 | 怎么搬 |
| --- | --- | --- |
| 数字当标题（48px + 强调色） | ✅ | 有真实数量的落地页第一屏就用它，别写形容词 |
| 无壳图墙 + 溢出裁切（露出 1.8 张） | ✅ | 作品/评测/截图列表；**必须配一个「查看全部」或 hover 提示**，否则就是本案例的第 6 条病 |
| 全站只有一个正方形尺寸（80 / r24） | ✅ | 头像、图标、封面都用同一尺寸，视觉重量才对得齐 |
| 双类目信息胶囊右上纵排（版本 + 数量） | ✅ | 后台列表行、素材卡；宽度由内容撑开、右对齐 |
| 24/16/6/4/2 线性圆角阶梯 | ✅ | 直接用；比「一律 8px」有层次 |
| 系统字体栈 + 全站 `line-height: normal` | ⚠️ | 只适合这种「工具型灵感库」；后台表格与正文别学，中文长文本 normal 会挤 |
| viewport 锁 1420 | ❌ | 这是最典型的反面教材 |
| 无页脚 / 无 h1 / 无限滚动无出口 | ❌ | 三条都属于「结构缺失」，验收清单里直接判不通过 |

混合口径（把它搬进产品后台时怎么改）：

- 截图槽 240×520 → 换成 4:3 缩略图，`aspect-ratio: 4/3`，`object-fit: cover`；
- 48px 大数字 → 后台 KPI 用 32px（和 `component-spec.md` 一致），落地页才留 48；
- `line-height: normal` → 后台正文改 1.5，表格 1.4；
- 促销条暖琥珀 → 要么删掉，要么改成与主色同色系的浅底，别并排两套。

## 八 复现清单（照着这十条就能做出同款）

1. 定一条竖轴：所有内容左右 32，容器 1376；三列 440 + 列距 28。
2. header 72 高、sticky、透明底、无边框；导航 15/400，右上黑胶囊 100×40 r20。
3. hero 用 90° 三停渐变（淡紫 → 淡粉 → 淡蓝紫），高 680。
4. 大数字 48/500，数字单独包 span 给 `#446bf8`；说明段 18/400 lh30，最大宽度 712，居中。
5. 图标墙三行、行高 110、图标 80/r24、横向滚动，两侧靠容器裁切（不要加渐变遮罩，它没加）。
6. 筛选条 56 高 + 底部 1px `#f1f2f4`，左两个下拉，右一行计数。
7. app 条目 440×626：图标行 92（80 + 12 + 名称/副标）+ 截图带 520。
8. 截图带用 `overflow: hidden` 的固定宽容器，每张 240×520 r16 gap12，故意让第 3 张被裁。
9. 信息胶囊 32 高 / r6 / `#f8f8f8` / 13/400 `#666`，右对齐纵排间隔 8。
10. **补上它没做的四件事**：`<h1>`、移动端重排（≤640 两列、截图槽改 4:3）、hover 反馈（裁切处给「+3」）、页脚（备案 / 隐私 / 联系）。

## 九 与其他参考文件的关系

- 与 `page-patterns.md`：补第七类骨架「内容陈列 / 灵感库」的**第三种陈列方式**——前两种是 `uishijie-design.md`（密版、5 列 gap 0）与 `zcool-design.md`（疏版、4 列、有报头）；这一份是**活预览型**：卡片内容由真实素材本身构成，界面尽量隐形。
- 与 `stylekit-design.md`：两者都「卡片内容才是主角」，但 StyleKit 的预览是自己画的迷你 DOM（可控、可复制），UI Notes 的预览是别人的截图（不可控、必须裁切）。设计时先想清楚你手里是哪一种。
- 与 `css-recipes.md` §17：`--un-*` 令牌 + `.app-item` / `.app-shots` / `.shot` / `.pill-mini` / `.num-hero` / `.icon-wall` 的完整 CSS。
- 与 `design-evidence.md`：它是 A 组第 15 个样本（第 3 个内容站），把「正文字号」压低到 13px 的又一个证据。

## 十 重采方法

```bash
node scripts/probe-ref.mjs --url https://uinotes.com/ --out ./out --name uinotes --wait 6000
node scripts/screenshot.mjs --url https://uinotes.com/ --out ./shots --name un --full
```

三个坑：

1. **长图会因为懒加载截空。** 先滚动到底再截（`screenshot.mjs --full` 有滚动，但仍建议手动分段截），或直接用脚本切图：`python shot-split2.py un-desktop.png un-d 2400 1400`。
2. **`.sample` 在未滚动时 `src` 为空**（2×2 占位图），要量截图尺寸必须等懒加载触发。
3. **移动端测不到「重排」**，只会测到 `innerWidth = 1420` —— 这本身就是结论（见第六节第 1 条），不要误判成脚本出错。

## 结构证据（REA 被动采集，2026-10-31）

| 指标 | 值 |
| --- | --- |
| DOM 节点 | 1433 |
| 无障碍节点 | 562 |
| DOM 深度（最大 / 均值） | 13 / 10.1 |
| 地标 | 3 个：`banner` / `navigation` / `navigation` |
| 标题层级 | 无 heading |
