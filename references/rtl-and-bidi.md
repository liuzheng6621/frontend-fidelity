## 一、我们实测到的（4 条）

样本：`mozilla.org/ar`（阿拉伯语）、`mozilla.org/he`（希伯来语）。
两个站同属一套设计系统，**样本量不足**——这正是下面每条都要标等级的原因。

| # | 结论 | 数字 |
| --- | --- | --- |
| 1 | **RTL 布局靠 `dir="rtl"` 属性 + 浏览器镜像，不靠逻辑属性** | 阿拉伯站 457 个可见元素里 438 个 `direction: rtl`、19 个 ltr；样式表里逻辑属性 **2 条** vs 物理属性 **384 条**（占比 1%）。希伯来站更极端：**1 vs 342**（占比 0%） |
| 2 | **`body` 的 `text-align` 是 `start`，不是 `right`** | 两站都是 `start`。写死 `right` 会在切语言时错位 |
| 3 | **RTL 语料的字距基本是 `normal`** | 阿拉伯站 227 处文字元素全部 `normal`；希伯来站 161 处 `normal`，标题上有 `-0.16 / -0.18 / -0.48px` 的微负值 |
| 4 | **图标镜像不是普遍做法** | 两站镜像图标数均为 **0**。没量到任何 `scaleX(-1)` |

第 3 条对中文项目同样成立：**阿拉伯文是连写体，拉字距会把字形拆开**。
`letter-spacing` 在 RTL 正文上必须是 `normal`（`0`），只允许在标题上用极小的负值。

第 4 条是反直觉的：文档里说要镜像箭头，但两个真实站点一个都没镜像。
可能因为站点用图标字体/内联 SVG 不靠 transform。**别把「没量到」当成「不该做」**，见 §三。

## 二、基础方向与语言：`dir` 和 `lang` 要成对出现

【外部】整页 RTL 必须是 `<html dir="rtl" lang="ar">`（希伯来语 `he`、波斯语 `fa`、乌尔都语 `ur`）。
`lang` 决定字体栈、断词、朗读语音、搜索引擎索引——**只写 `dir` 不够**。

三种常见模式：

| 场景 | 写法 |
| --- | --- |
| 整页 RTL | `<html dir="rtl" lang="ar">`，内部全部继承 |
| 混合语种子树 | 嵌一段 `<section dir="ltr" lang="en">…</section>`（代码块、英文引用、外文品牌名） |
| 方向未知的用户内容 | 段落上 `dir="auto"`，浏览器按第一个强方向字符判断 |

两条容易写错的：

- 默认 LTR 页面的**根节点**只写 `lang` 不写 `dir` 是可以的（英语不需要 `dir="ltr"`）。
  但在**任何反向祖先内部**，`lang` 不会重置继承来的基础方向，必须 `dir` + `lang` 一起写在子树上。
- 只写 `dir` 不写 `lang` 几乎总是错的——至少补上正确的 ISO-639 标签。

## 三、什么镜像、什么不镜像

【外部】M3 RTL 指南与 Apple HIG 国际化的结论一致，不是风格偏好。

**必须镜像：**

- 方向性箭头（返回 / 前进 / 下一步 / 上一步）、导航栏位置、Tab 顺序、日历星期排列顺序。
- 滑块填充方向、**非媒体类**进度条填充（下载进度、表单完成度、上传状态）。
- 复选框与标签的位置：LTR 标签在右，RTL 标签在左。

**绝不镜像：**

- 钟面。顺时针是普适的。
- 圆形刷新 / 同步 / 重载图标，同理。
- **媒体播放控件**（播放 / 暂停 / 快进 / 快退）**以及播放进度条**——它们表示磁带方向，不是阅读方向。
- 图表。X 轴是数学方向，不是语言方向。
- 照片、品牌 Logo、实物图标（相机、键盘、耳机）。身份优先于方向。

**唯一一个平台冲突**：搜索图标。SF Symbols 提供 RTL 变体（Apple 会翻），
M3 明确说不翻（手柄在右下）。**按平台各自决定，不要合成一条统一规则。**

## 四、数字与混排：`<bdi dir="ltr">` 要显式写

【外部】数字不跟着段落方向走，它跟**区域设置**走。阿拉伯-印度数字的 bidi 类别是 **AN** 而非 EN。

当一个 RTL 段落里出现手机号、IBAN、订单号这类**以数字为主**的值时，用
`<bdi dir="ltr">`（或 `<span dir="ltr">`）把它包住，让数字不重排。

**光写裸 `<bdi>` 不够**：手机号和账号里大量是弱字符/中性字符，
「第一个强方向字符」的判断不可靠，必须显式给 `dir="ltr"`。

## 五、逻辑属性是首选，但要知道现实

【外部】写 RTL 优先用逻辑属性：`margin-inline-start` / `padding-inline-end` /
`inset-inline-start` / `border-start-start-radius`，一套 CSS 同时服务两个方向。

【实测】但上面两个 Mozilla 站几乎不用逻辑属性（1% 和 0%）——它们走的是
**镜像样式表 / `[dir=rtl]` 覆盖**这条路。

所以落地时二选一，别混：

| 路线 | 适合 | 代价 |
| --- | --- | --- |
| 逻辑属性 | 新项目、组件库、要长期维护 | 老浏览器要 `postcss-logical`，团队要改习惯 |
| `[dir=rtl]` 覆盖 | 已有大量物理属性的大项目 | 样式翻倍，容易漏 |

**混着写是最糟的**：一半逻辑一半物理，改一次方向两边都要查。

## 六、排版

- **字距**：【实测】RTL 正文 `letter-spacing: normal`。阿拉伯文连写，拉字距会拆字形。
- **行高**：【实测】两站正文都是 `1.5`；希伯来站标题压到 `1.1`，阿拉伯站 H1 用 `1.5`。
  结论：**行高不比中文高**，别照搬「RTL 要更松」的说法。
- **字体**：不要拿中文字体栈去渲染阿拉伯文/希伯来文——字形会回退到系统默认。
  按 `lang` 给字体栈，例如 `:lang(ar) { font-family: "Noto Naskh Arabic", "Geeza Pro", system-ui }`。

## 七、常见错误（逐条可查）

- 只写 `dir="rtl"` 不写 `lang`，或反过来。
- `text-align: right` 写死。用 `start`。
- 用 `margin-left` / `padding-right` 做间距，再靠覆盖表补 RTL。
- RTL 段落里的手机号没包 `<bdi dir="ltr">`，数字被拆到行首。
- 把播放进度条也镜像了（媒体控件不镜像）。
- 把图表 X 轴镜像了（数学方向不跟语言走）。
- 给阿拉伯文正文加 `letter-spacing`。
- 拿中文/拉丁字体栈渲染阿拉伯文。
- 镜像了 Logo 和照片。
