# 稀土掘金：文字信息流的「三栏工作台」

单站实测（2026-10-27，Playwright Chromium，未登录，浅色，1440×900 与 390×844）。
采样地址 `https://juejin.cn/`，原始探针约为 16:04 / 16:08，axe 审计为 16:18，定向复测约为 16:28（均为 UTC+8）；证据含两视口全页截图、首页静态图、探针 JSON、axe 4.14.0 与结构审计，动态文章不同，以下以布局与计算样式为准。

> **一句话：灰底上的三栏工作台，中间是一整张白色文章列表，不是一叠文章卡。**
> 它适合中文技术社区、新闻列表与更新流；重点不是功能多，而是全局导航、频道、排序、正文、运营位各有固定层级。
> 采样只覆盖首页两个视口，不推断中间断点、登录态或其他页面。

本次可见节点没有支持一套 6/8px 通用圆角阶梯，不要补造。

## 三、排版：字阶少，职责不能混

字体是系统栈，不是单独 Arial；中文正文不下载 webfont 是合理取舍，Arial 只在栈尾：
`-apple-system, system-ui, Segoe UI, Roboto, Ubuntu, Cantarell, Noto Sans, sans-serif, BlinkMacSystemFont, Helvetica Neue, PingFang SC, Hiragino Sans GB, Microsoft YaHei, Arial`。

| 元素 | 字号 / 行高 / 字重 | 颜色 |
|---|---|---|
| 文章标题 | 16 / 24 / 600 | `#252933` |
| 摘要 | 13 / 22 / 400 | `#8a919f` |
| 作者与动作行 | 13 / 22 / 400 | `#8a919f` |
| 标签 | 12 / 18 / 400 | `#8a919f`，`#f2f3f5` 底 |
| 左频道 | 16 / 24 / 400，选中 500 | `#515767` / `#1e80ff` |
| feed 排序 | 15.96 / 24 / 400，选中 500 | `#909090` / `#252933` |

| 搜索与按钮 | 13–14 / 400 | 按控件角色 |

首页采样未见 `h1`、`h3`；原始探针的 `h2=16/24/500` 与 `p=14/21/400` 来自隐藏登录/下载弹层。
因此它们不能替代 feed 字阶，也不据此虚构 26px H1、20px H2 或 1.46 的全站行高；迁移时应补一个视觉不抢戏的页面 `h1`，文章标题再用合理 heading 层级或链接命名。

## 四、布局与导航层级

```text
60     全局顶栏：品牌 / 产品导航 / 搜索 / 创作者 / 登录
20     主区顶间距
       180 左频道 + 20 + 720[49 排序 + 文章列表] + 20 + 260 右栏
```

1. **全局导航在顶栏，频道在左栏，排序贴着 feed。** 三层不共用同一种胶囊，层级由位置与尺寸承担。
2. 左栏 `position:sticky`，初始 `top:80px`；右栏是 `absolute`，滚动 800px 后随文档离开，不是整栏 sticky。
3. 滚动复测时左栏计算 `top` 由 80 变为 20，而 60px 顶栏仍在 0–60；这是动态行为，是否预期需人工复核，别直接照抄。
4. 移动顶栏压到 52px，保留下拉式「首页」、搜索与登录；第二行保留约 46px 高的横向频道条，再接 49px 排序行。
5. 移动隐藏左频道、右栏、悬浮下载面板与条目标签；**没有隐藏缩略图**，也没有把文章改成大图卡。

### 逐模块

- **顶栏**：桌面 logo 链接 107×58.7；搜索、创作与登录从右向左收束。移动 logo 链接只剩 31px 宽，搜索缩到 140px。
- **左频道**：180px 白底 r4，包含排行榜与 9 个内容频道；频道项左右各留 8px，实际可点项宽 164px。
- **feed**：先排序再列表，整张白壳统一 20 个采样条目；条目不重复画壳，靠分隔线保持连续扫描。
- **右栏**：当前可见顺序只有 **AI Coding 运营卡（259.91×74、padding 16、下间距 20）→ 协议/备案页脚**。
- **右栏边界**：签到、其他广告、推荐作者、话题、下载卡片在本次可见 DOM/截图中未出现，顺序均**未验证**，不能凭历史版本补写。
- **独立浮层**：登录礼包与「下载 APP / 微信 / 微博」悬浮面板不属于右栏文档流；移动截图里登录礼包直接遮住 feed。

## 五、feed 条目配方

```text
li.item                                  720×99（移动 390×99）
  内容区                                 padding: 12px 20px
  标题                                   16/24/600，单行省略
  摘要                                   13/22/400，单行省略，下间距 4
  元信息                                 作者 / 阅读 / 点赞，13/22
  右侧标签                               12/18，padding 0 6，左间距 6
  可选缩略图                             110×74，margin-left:24，cover
```

无图时桌面文字区宽 680；有图时为 546，外加 24 间距与 110 图片，仍占总内容宽 680。
移动无图文字宽 350，有图压到 216；**变的是文本列宽，不是条目高度和图片尺寸**。
这保证了有图/无图混排仍像同一条流，但 216px 下长标题损失很大，迁移时应允许两行标题或缩短摘要，而不是继续缩字。

## 六、组件状态、响应式与动效

- 当前频道是「浅蓝底 + 蓝字 + 500」；未选频道是 400 的 `#515767`，不要只靠颜色表达选中。
- 「最新」排序 hover 从 `#909090` 变为 `#1e80ff`，计算 transition 为 0s；采样文章标题 hover 无变化。
- 创作者按钮只改背景：`#1e80ff → #1171ee`，`background-color 100ms linear`，没有位移与缩放。
- 原始探针 `animations=0` 只表示未检出 CSS animation，**不等于没有 transition**；完整交互与 reduced-motion 未验证。
- `active / disabled / loading / empty / error` 与键盘 `focus-visible` 均未验证；迁移必须自行补齐可见焦点和异步状态。
- 响应式只能确认 1440 三栏、390 单栏；中间宽度、横屏和断点未测，禁止编造 768/960/1200 等阈值。

## 七、性能与图片：只评这一次首页采样

| 指标 | 桌面 | 移动 |
|---|---:|---:|
| 图片 / lazy | 20 / 16 | 19 / 15 |
| CLS | 0.0000315 | 0.000130 |
| HTTP error | 0 | 0 |
| `parseImageXUrl` console error | 14 条 | 13 条 |

固定 110×74 图片框与 80% 左右的 lazy 占比，是这条密度流值得迁移的部分；单次低 CLS 不代表全站性能结论。
缩略图有文章标题作 alt，且 `object-fit:cover`；若内容必须完整可读，应改 `contain`，否则保留裁切并固定尺寸；图片 URL 解析报错需另查，不要因为 CLS 低就忽略 console。

### `logo-distorted` 必须纠正口径

桌面 11 条、移动 12 条该规则命中全部为 `img.lazy.thumb`，显示比均约 1.49，而原图比例各异。
审计规则用 `/logo|brand|mark/` 匹配 `src + alt + class`，这些缩略图 URL 的 `jj-mark-v1` 中恰好含 `mark`。
所以这是**内容缩略图被 cover 裁切触发的规则误报**，不是「掘金 logo 全拉伸」，也不能据此要求缩略图按原比例撑高列表；真实品牌 logo 未成为这些命中节点，审计器应排除内容图或结合 `object-fit` 与明确选择器再报。

## 八、可访问性与七处别照抄

审计页面均为 `https://juejin.cn/`，时间是 **2026-10-27 16:18（UTC+8）**，不是跨站排名。
桌面汇总 184 error / 1 warn，移动 122 / 22；总数混合 axe 节点和结构规则，不等于 184 / 122 个独立缺陷。
axe `color-contrast` 为桌面 152 处、移动 87 处；`list` 各 1，`listitem` 各 20，移动另有 `label` 1。
桌面 184 中包含上述 11 条图片误报，移动 122 中包含 12 条图片误报与 1 条溢出，解读时必须拆开。

1. **别照抄灰字和蓝字对比度。** `#8a919f/#fff=3.17:1`，`#909090/#fff=3.19:1`；`#1e80ff/#fff=3.76:1`，白字同蓝底也只有 3.76:1，均不达普通小字 AA。
   `#007fff/#f4f9ff=3.62:1`、`#1e80ff/#eaf2ff=3.34:1` 也被 axe 命中；迁移时正文灰可改 `#6b6b6b`（5.33:1），品牌色也要另选更深行动色。
2. **别照抄列表语义。** `.main-nav > ul.nav-list` 直接嵌了不允许的 `ul`；feed 的 `li.item` 又直接位于 `div.entry-list.list` 下。
   修正为真实 `ul/ol > li`，或给恰当容器 `role=list`，不要只修 axe 表面数量。
3. **别照抄无标签搜索。** 移动 `input.search-input` 无 `<label>`、无 `aria-label`，placeholder 也为空，axe `label=critical`。
4. **别禁止缩放。** 两视口均有 `user-scalable=no` 的 `meta-viewport` 警告；信息密集更需要允许用户放大。
5. **别忽略 4px 横向溢出。** 390 下 `scrollWidth=394`；逐节点隔离后，隐藏顶栏 `.main-header .container` 即恢复 390。
   该容器 x=15.98、宽 378.30、右缘 394.28；应修它的宽度/外边距约束，不能用全局 `overflow-x:hidden` 掩盖。
6. **别只让文字可点。** 移动报告列 20 个小点击区并注明另有 43 个：标题高 24、摘要/作者 22、搜索 32、登录 36，logo 宽 31。
   把整块标题区或条目主链接扩到至少 44px 高，同时避免覆盖作者、标签等独立链接。
7. **别让登录礼包压住正文。** 移动全页截图中浮层覆盖多条 feed；运营弹层应有明确关闭、频次上限与不遮挡核心阅读的布局。

## 九、可迁移手法

| 手法 | 适用 | 迁移时的约束 |
|---|---|---|
| 1200 三栏：导航 / feed / 运营 | 技术社区、资讯首页 | 两个 20px 间隔比三栏都等宽更重要 |
| 一整张白列表，条目不画卡 | 高密度文字流 | 用分隔线，不给每条加阴影和 16px 外距 |
| 有图无图共用条目骨架 | 混合 UGC | 图片固定 110×74，文本 `min-width:0` |
| 标题 / 摘要 / 元信息三层 | 中文文章列表 | 摘要可删，主标题与作者不能只剩浅灰小字 |
| 顶栏—频道—排序三级导航 | 多频道社区 | 当前项同时给形状/字重/颜色，不只换蓝 |
| 移动保留频道与缩略图 | 阅读优先的窄屏 | 隐藏左右栏与次要标签，不牺牲主内容识别 |
| 右栏只放次级运营与页脚 | 有商业位的首页 | 不让浮层混入文档流顺序，也不凭记忆堆模块 |

**混合口径：** 可以借站酷的选中形状纪律、UI 世界的内容优先，但不要借它们桌面图墙密度。
掘金的 13px 摘要和 12px 标签也应视为上限密度而非可访问性范本；先过对比度，再谈压缩行高。

## 十、搬用步骤

1. 先建 `#f2f3f5` 页面底、白色面板、主/次文字与一个行动蓝；把「原站实测」与「AA 修正值」分开命名。
2. 主容器 `max-width:1200px; margin-inline:auto`；桌面按 `180px minmax(0,1fr) 260px`、20px 栏间距排，达到上限时中栏为 720。
3. 顶栏 60px sticky；左栏 sticky 的 top 与顶栏统一计算，右栏是否跟随滚动按业务决定，不复刻 80→20 的动态偏移。
4. feed 白底 r4、无阴影；先放 49px 排序行，再放连续列表，条目间只画一条分隔线。
5. 条目以 99px 采样值起步，左右 20、上下约 12；标题 16/24/600，摘要 13/22，标签 12/18。
6. 可选缩略图固定 110×74、左间距 24、`cover`；有图时压缩文本列，不改图片尺寸，并提供恰当 alt。
7. 搜索、创作者、登录按 34/36px 采样高度做桌面密度，但另扩键盘焦点与移动点击区，不能照搬 18px 标签命中区。
8. 窄屏切单栏，隐藏左右栏和次级标签，保留横向频道、排序与缩略图；断点由本项目内容测试决定。
9. 右栏只放真实存在的模块；本次可复现的是运营卡→页脚，签到/作者/话题等需另采样后再定顺序。
10. 验收跑 1440 与 390：逐条看 contrast、list/listitem、label、缩放、点击区、浮层遮挡；另断言 `scrollWidth===innerWidth`，并人工复核图片规则命中。

## 结构证据（REA 被动采集，2026-10-31）

> 采集地址 `https://juejin.cn/`，1440×900 无头 Chromium，CDP 被动读 DOM 与无障碍树：不执行脚本、不点击、不导航。
> 数字是采集时刻的快照，样式数值见 `references/design-evidence.md`；本层只回答「结构怎么搭」。

| 指标 | 值 |
| --- | --- |
| DOM 节点 | 2605 |
| 无障碍节点 | 1190 |
| DOM 深度（最大 / 均值） | 27 / 18.1 |
| 地标 | 8 个：`banner` / `main` / `navigation` / `navigation` / `complementary` / `region:进行中的活动` / `navigation` / `search` |
| 标题层级 | h2×1 |
| 语义标签 | `header`×2 `nav`×5 `main`×1 `section`×3 `aside`×1 `form`×1 |
| 带 aria-* 的元素 | 11 |
| 图片 alt 覆盖 | 22/22 |
| 链接 / 图片 / 按钮 / 标题 | 134 / 69 / 7 / 1 |
| 标签频次 Top 6 | `div`×405 `a`×148 `li`×136 `span`×123 `svg`×91 `circle`×85 |

**判读**：8 个地标（banner / main / 3 个 navigation / complementary / region「进行中的活动」/ search）——**样本里地标最细的一个**：活动区用 `region` 命名、搜索用 `search` 地标，两者都不靠 class 表达。整页只有 1 个标题（`h2`，**没有 h1**），信息层级靠 5 个 `nav` 切区。深度均值 18.1，偏深。
