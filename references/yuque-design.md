# 语雀 yuque.com 设计蒸馏（实测，2026-10-27）

> 样本：`https://www.yuque.com/` 公开首页；目标是提炼中文 SaaS / 知识工具首页的可复用设计规格。
> 这不是产品介绍，也不是官方设计令牌清单；下文“迁移建议”均与“原站实测”分开写。

## 四、设计手法：色板与绿色用法

| 角色 | 实测值 | 用法 |
| --- | --- | --- |
| 主文字 | `#000000`、`#262626` | 大标题与正文，黑字先于品牌色建立阅读层级 |
| 次文字 | `#585a5a`；Hero 桌面 `#7f7f7f`、移动 `#595959` | 描述与辅助信息，不用彩色承担所有层级 |
| 页面与卡片 | `#ffffff`、`#fafafa` | 主页面、作品与页脚，主要靠明度分段 |
| 冷浅底 | `#f8f9fa` | 数据安全段；随附 `#f8faf9` 同属近白浅底口径 |
| 品牌绿 | `#00b96b` | 主按钮、当前功能项、个人场景与黑底强调字 |
| 绿色渐变 | `#00b96b → #21ce85` | 只给个人场景，不全页重复 |
| 团队蓝渐变 | `#166eff / #2174fc → #319ff6` | 只给团队场景，与个人绿形成角色编码 |
| 深色段 | `#000000` | 下载与公益两段，不当普通卡片底色滥用 |

绿色的可辨识性来自**少量高价值位置**：一个主行动、一个当前项、一个角色场景，而不是每张卡都描绿。
黑字大标题与绿色行动形成第一组对比；黑底公益段再用绿色短句形成第二组对比，前后呼应但不连续铺绿。

对比度按 sRGB 复算：`#00b96b` 配白字 **2.58:1**、配黑字 **8.15:1**；随附 `#36b368` 配白字也只有 **2.69:1**。
所以“黑绿对比”可学，绿底白字的小按钮却不能视为无障碍通过；迁移时应加深绿或改用足够深的文字。
另 `#787878` 在白底为 **4.42:1**，普通小字略低于 4.5:1，也应稍加深而非直接照搬。

## 五、设计手法：字体、圆角与间距

- 原站计算栈是 `Chinese Quote → -apple-system/BlinkMacSystemFont → Segoe UI → PingFang SC → Microsoft YaHei → sans-serif`。
- 随附 `system-ui` 可作为**迁移近似方案**，但不能据此宣称原站没有网络字体；本次确有已加载的 `Chinese Quote` 字体面。
- 中文营销标题靠 600/700 与短行取胜，不使用斜体、手写体或第二展示字体。
- Hero 与 h2 是展示字阶；后台正文仍应回到 14–16px，不能把 100/60/30 全部带进产品界面。
- `r6` 给登录、下载等小按钮；`r11` 给 Hero 双 CTA；`r14` 给工作台大图；`r38` 只给双场景大卡。
- 工作台阴影实测为 `0 8px 16px 4px #0000000a`、`0 2px 8px #00000014`、`0 1px 4px -2px #00000021` 的近似 RGBA 对应值。
- 阴影只把截图从白底托起；双场景卡无阴影，靠实色渐变与 `overflow:hidden` 成形。
- 微间距沿用随附 `8/12/16/24/32` 口径；章节间距另算，不强迫所有距离进入同一档。
- 桌面章节常见上 padding 105/135/140，功能预览下 margin 200，双场景段为 105 上 / 180 下。
- 移动大块统一感来自 **60px 纵向 + 22px 横向**；Hero 则用 24px 横向，不把桌面留白等比缩小。

## 六、设计手法：栅格与产品预览

- 桌面主容器为 **1140px**，在 1440 视口中左右各 150；不是常见的 1280 满宽容器。
- Hero 左栏约 **559**、右栏容器约 **581**；标题、20px 描述、双 CTA 沿同一左缘对齐。
- 工作台面图源为 **1860×1076**，桌面渲染 **930×538**，正好 2 倍密度；`r14`，非低清截图放大。
- 图片从 x=764.59 延伸到 1694.59，桌面右缘被视口截去约 255px，形成“工作台冲出页面”的出血构图。
- 双场景桌面是 **631 + 460** 的非等分组合，高均 456；几何间隙约 49，不能仅读 CSS gutter 就当视觉间距。
- 移动双场景改为两张 **346×250.84**，间隔 24，圆角仍 38；宽度收缩而非把桌面两卡硬挤一行。
- 编辑器桌面是左功能列表、右产品图；知识库左右互换。移动都改成**上图、下列表**，保留交替感但不牺牲阅读。
- 移动 Hero 图渲染 **432.14×250**，右缘到 456.14；在 390 视口被截约 66px，父容器本身 `overflow:visible`。
- 真正阻止横向滚动的是 `.official-layout { overflow-x:hidden }`：移动 `document.scrollWidth=390`，没有页面级横向滚动条。
- 截图构图像有意保留左侧工作台并右缘出血，但**设计意图未验证**；迁移要给完整预览入口，不能靠 hidden 掩盖失控布局。

## 七、设计手法：场景、角色与资源证据

1. **双场景先分角色**：个人绿、团队蓝，标题 28/16，图放在卡内下部；颜色直接承载“这是谁的工作方式”。
2. **功能段用真界面解释**：编辑器与知识库不是四张泛化图标卡，而是产品截图配可选功能列表，当前项绿、其余灰。
3. **下载黑段改变节奏**：在两大功能之后用纯黑全宽段收束，再把八个入口放在同一行/网格中。
4. **作品瀑布流承担使用证据**：桌面三列真实文档/画板/图片混排；它是作品陈列，不应改写成虚构客户语录。
5. **安全与组织是两类信任证据**：先三项安全认证/能力，再多行组织 logo；不要把两种证据混成一排无解释 logo。
6. **公益黑段是第二次深色收束**：与下载段同底但内容更聚焦，绿字只给核心短句与一个详情入口。
7. **页脚回到浅底**：品牌/社群与三组链接分区，最后才是备案；移动端链接分组保留，但版式与点击区需要重做。

## 八、实测事实：控件、移动、动效、性能与无障碍

- 桌面登录按钮约 **121×40 / r6**；Hero 双 CTA 均 **198×57 / r11**；下载按钮 **146×48 / r6**。
- 移动登录约 **121×40**，Hero CTA **116×40**；多个下载按钮只有 **105×24**，不能按桌面密度直接验收。
- 控件过渡实测 `0.3s cubic-bezier(.645,.045,.355,1)`；登录 hover 绿色加深，没有位移或大阴影。
- 定向聚焦时三个首屏按钮可匹配 `:focus-visible`，但计算 `outline` 为 0；次按钮没有清晰焦点差，完整 Tab 流程**未验证**。
- 移动页头不是折叠成汉堡菜单，而是 **9 个导航链接全部消失**，只留下 logo 与“登录 / 注册”。
- 进入视口的 `fadeInUp` 为 **1000ms linear**；团队卡延迟 200ms，下载列表延迟 500ms。
- 组织 logo 带为 **50s linear 无限循环**；移动滚动后同样出现这些动画，减少动效回退**未验证**。
- 双端均有 **36 张 img，`loading=lazy` 为 0**；稳定采样时全部 complete、自然尺寸非 0，但离屏懒加载不足是性能风险。
- 桌面审计 **0 error / 1 warn / CLS 0**；唯一 warn 是 CSP 阻止注入 axe，不是“全部通过”。
- 移动审计 **2 error / 17 warn / CLS 0.0734569**；17 warn 由 16 条小点击区与 1 条 axe 注入失败构成。
- 两个 overlap 都在页脚备案：ICP 链接分别与“合字 B2”重叠 **109.55×19**、与公安备案重叠 **175.66×19**。
- 这不是导航或主 CTA 重叠：ICP 换行后的 **333.31×41** 包围盒，分别与第一行“合字 B2”、第二行公安备案的 19px 高包围盒相交；不把它扩大解释为全页视觉重叠。
- `axe:0` 且 `axe:null` 表示**没有有效 axe 结果**，不能写成“axe 检出 0 个问题”；需绕过 CSP 合法复测或本地等价审计。
- CLS 约 **0.073**，低于常用 **0.1 良好/需改进分界**，属于过门槛但接近、需继续关注；不能夸大为差档。

## 九、可迁移手法

| 手法 | 迁移规格 | 适用理由 |
| --- | --- | --- |
| 黑字 Hero + 一个绿色主行动 | 标题先做阅读层级，品牌绿只给主 CTA 与当前态 | 中文 SaaS 容易显得专业而不花哨 |
| 真实工作台作为 Hero 证据 | 用 2x 图、r14、轻三层阴影；文案与图共享一条基线 | 用户先看到产品，再读抽象承诺 |
| 绿/蓝双角色场景 | 只选两个角色；桌面可非等分，移动等宽堆叠 | 颜色有信息含义，不是装饰色撒点 |
| 功能截图 + 当前项列表 | 当前项品牌绿，其余中性灰；移动统一上图下列表 | 能复用到文档、协作、知识库等工具首页 |
| 宏观/微观两套间距 | 组件 8–32；章节桌面 105–140、移动 60 | 既有呼吸感，也避免移动端空洞 |
| 白/浅灰成段，黑段只收束 | 内容段用白/近白，下载或专项 CTA 才用黑 | 比连续卡片和连续深色更易扫读 |
| 证据链而非卡海 | 功能 → 作品 → 安全 → 组织，缺少哪类证据就删哪段 | 适合知识工具建立可信度，无需编客户评价 |
| 系统字体 + 响应式字阶 | 迁移可用 system-ui；展示标题与正文分开定义 | 中文跨平台稳定，避免为风格引入多余字体 |

## 十、七处别照抄

1. **别把首页塞进内部滚动容器还当普通文档流。** 它让 document 永远只有一屏，截图、锚点与滚动验收都容易失真。
2. **别用 div 充当唯一 Hero 标题。** 本次首页未找到 h1；迁移必须补语义 h1，而不是只复刻 100px 外观。
3. **别照搬绿底白字。** 2.58:1 不满足普通文字 4.5:1，也未达到大字 3:1；先改色再谈品牌还原。
4. **别把移动导航直接删光。** 只留登录会让产品、价格、安全与帮助入口消失，应提供可键盘操作的折叠菜单或精简导航。
5. **别接受“能点”就当移动可用。** 24px 高下载按钮、19px 高备案链接及两条页脚重叠都要修，点击区至少 44×44。
6. **别用 `overflow-x:hidden` 证明响应式正确。** Hero 是有构图的裁切，但其他内层也有越界；需逐项区分出血设计与布局失控。
7. **别把 1s 直线入场和 50s 无限 logo 带当必备气质。** 减少动效回退尚未验证；迁移应先有静态可读版，再按需增强。

## 十一、搬用步骤

1. **先排证据顺序**：Hero → 双角色 → 两组核心能力 → 下载/行动 → 真作品 → 安全 → 组织 → 页脚；无真实内容的段直接删。
2. **恢复正常文档滚动**：若产品壳必须内部滚动，同步定义锚点、滚动恢复、截图与审计的容器目标。
3. **定语义色而非堆 hex**：确认 `#36b368` / `#00b96b` 的版本口径，只留一支主绿；蓝只给第二角色。
4. **先修对比度**：主按钮达到文字对比要求，次文字在白底 ≥4.5:1，再谈渐变和浅色底。
5. **用语义标签落字阶**：唯一 h1 管 Hero；迁移可试 `clamp(44px,7vw,100px)`，h2 可试 `clamp(28px,4.2vw,60px)`，正文 14–16。
6. **落栅格**：桌面从 1140 容器起步，移动先用 22–24 页边距；断点由内容实测决定，原站精确断点标**未验证**。
7. **做真产品预览**：准备 2x 工作台图、r14 与轻阴影；若采用右缘出血，同时提供完整图或详情入口。
8. **做两类场景与两类功能展示**：双卡只编码两个角色；功能列表保留当前/默认/焦点态，移动改为图与列表上下排。
9. **补齐控件与页脚底线**：主要触控区 ≥44×44，补显眼 `:focus-visible`，逐个验证 hover/focus/active/disabled 与备案换行。
10. **最后做性能与双端验收**：离屏图懒加载、给 CLS 留足 0.1 以下余量、验证 reduced-motion，并对实际滚动容器分段截图与审计。

## 十二、与 wegic / jsdesign 的差异

| 维度 | 语雀 | Wegic | 即时设计 js.design |
| --- | --- | --- | --- |
| 核心气质 | 白底黑字、绿色行动、真实知识工作台 | 纯黑舞台、暖白内容、塑料按钮与手写批注 | 冷灰蓝底板、白卡与彩色纸卡 |
| Hero | 100px 短句 + 大幅工作台出血图 | 86.4px 逐字入场 + 提示输入框 | 40px h1 + 彩虹渐变 + 输入按钮组 |
| 叙事重心 | 角色 → 功能 → 作品/安全/组织证据 | 深色滚动叙事 → 模板/感言/FAQ | 功能 → 流程 → 对比 → 更新日志 |
| 强调色 | 绿为主，蓝只标团队场景 | 黑白为主，薄荷绿与活动橙分职责 | 主蓝贯穿，三色 pill 编码流程阶段 |
| 深度语言 | 双场景扁平实色；截图 r14 + 轻三层阴影 | 内阴影厚度、发丝圈、暖白表面 | 负扩散阴影 + 发丝环，大截图另用浮空影 |
| 移动策略 | 导航隐藏、模块堆叠、Hero 右裁；动画仍保留 | 桌面 8 个动画到移动 0，明显做减法 | 保持长页结构，但促销与遮挡问题更突出 |
| 最值得借 | 中文工具首页的证据链与真产品预览 | 按钮材质与深浅段落对照 | 章节节奏、阶段色与对比结构 |

一句话分工：**语雀适合“让用户相信这个知识工具真的可用”，Wegic 适合沉浸式产品叙事，jsdesign 适合流程与能力对比。**
三者的大标题、长滚动和营销控件都不能原样搬进管理端；语雀这份尤其要同时搬“证据顺序”，而不是只搬绿色与大截图。
