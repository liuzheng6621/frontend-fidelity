# 文案与信息架构

界面「像不像 AI 生成的」，一半看视觉，一半看文字。这份文件给可直接套的公式与长度预算。

三条总则：

1. **具体压过抽象**。「3 分钟生成一版页面」比「高效提升生产力」有用一百倍。
2. **数字要有口径**。「服务 2000+ 团队」不写「（截至 2026-02，含试用）」就是虚的。
3. **动词开头，对象结尾**。按钮与标题都适用：「导出订单」而不是「订单导出功能」。

---

## 一、长度预算（超了就删，不要缩字号）

| 位置 | 中文上限 | 备注 |
| --- | --- | --- |
| 页面主标题（H1） | 12–16 字，最多 2 行 | 营销页可到 20 字 |
| 区块标题（H2） | 8–14 字 | 一句话说清这一块干什么 |
| 卡片标题 | 4–8 字 | 不要用整句 |
| 正文段落 | 每段 ≤3 行 | 长内容改列表 |
| 列表项说明 | ≤1 行 | 超了用第二行缩进 |
| 按钮 | 2–5 字 | 「保存」「创建订单」 |
| 表单项标签 | 2–6 字 | 不要带冒号 |
| 帮助文本 | ≤20 字 | 一行内 |
| 错误提示 | ≤24 字 + 修法 | 见 §四 |
| 空态标题 | ≤12 字 | 「还没有订单」 |
| 导航项 | 2–4 字 | — |
| 表格列名 | 2–6 字 | 数字列带单位 |

英文字数换算：同一条中文按 2–2.5 倍字符宽度算。混排时以「最长那行能否放在 1024 宽的三栏里」为准。

## 二、标题公式

- 营销 H1：`[动作] + [对象] + [结果]` ——「创建网站，助力业务增长」是合格线；更好的版本带约束：「30 分钟上线一个能收款的产品页」。
- 后台页标题：名词短语，直接说是什么 ——「订单列表」「结算设置」。不要「订单管理模块」。
- 区块 H2：问题式或结论式均可，但**不要每条都用疑问句**（连用三条就是模板味）。
- 空态标题：说清「没有什么」——「还没有订单」，后面接行动而不是安慰。
- 状态标题：说清「发生了什么」——「已暂停」而不是「状态异常」。

**禁止**：标题里出现「一站式」「全方位」「重新定义」「下一代」「无缝」「极致」。
这些词不提供信息，只提供语气。

## 三、按钮与动作

公式：**动词 + 对象**（对象可从上下文继承时省略）。

| 场景 | 好 | 差 |
| --- | --- | --- |
| 提交表单 | 保存 / 创建订单 | 确定 / 提交 |
| 取消 | 取消 | 返回（返回 ≠ 取消修改） |
| 删除确认 | 删除 3 条订单 | 确定 |
| 重试 | 重新加载 | 点击重试 |
| 空态 | 新建订单 | 去创建 |
| 危险退出 | 退出登录 | 好的 |
| 上传 | 选择文件 | 浏览… |

- 同一页面的动作语态一致：都用动宾，不要「保存」配「确定」。
- 破坏性动作按钮上**写出后果**（「删除」而不是「确定」），并在上方说明不可恢复。

## 四、空 / 错 / 载文案公式

- 空：`[还没有 X]` + `[为什么空 / 能做什么]`（一行）+ `[一个行动]`。
  例：标题「还没有订单」／说明「客户下单后会出现在这里，你也可以手动补录」／按钮「新建订单」。
- 错误：`[发生了什么]` + `[可能原因]`（可选）+ `[怎么修 / 重试]`。
  例：「保存失败：分类名称重复」／「换一个名称，或先删除已有分类」／按钮「重试」。
  绝不出现：`Error 500`、`请求异常`、`系统繁忙，请稍后再试`（后者等于没说）。
- 加载：不需要文案。超过 1 秒才显示骨架，超过 10 秒加一行「还在加载，网络可能较慢」。
- 权限：`[你没有 X 的权限]` + `[找谁申请]`。不要用「暂无数据」掩盖无权限。

## 五、中文标点与空格（细节决定专业度）

- 中文用全角标点：`，。；：？！「」`；英文、数字、代码用半角。
- 并列结构用顿号 `、`；书名用《》；引号优先「」，内层用『』。
- **中英文之间留一个半角空格**：「支持 PDF 与 CSV 导出」，不要「支持PDF与CSV导出」。
- 数字与单位之间不加空格（「12px」「3 天」「5 分钟」里，中文量词前留空格更稳：`3 天`）。
- 省略号用 `…`（一个字符），不要三个点。
- 破折号用 `——`（两个），不要 `-` 或 `--`。
- 不用感叹号堆情绪（`！` 一屏最多一个，通常零个）。
- 时间格式统一：`2026-02-14 15:30`，不混用 `2/14` 与 `14 Feb`。

## 六、数字与单位

- 千分位：`1,280`（表格内）、`1280`（正文句子内，视场景统一）。
- 大数：`1.2 万 / 3 亿`，同一页面口径一致；不要一处 `12000` 一处 `1.2 万`。
- 百分比：`12%`（与中文混排也用半角 %），带上基数口径。
- 金额：`¥ 1,280.00` 或 `¥1,280`，全站统一到分或到元，**不要混**。
- 计数与单位之间：`3 个订单`、`5 条记录`；量词不能省。
- 表格内数字一律 `font-variant-numeric: tabular-nums`，右对齐。

## 七、语气（跟人格走）

| 人格 | 语气 | 例句 | 避免 |
| --- | --- | --- | --- |
| rational（理性/后台） | 陈述句，最短路径 | 「筛选条件已保存」 | 拟人化、感叹号 |
| editorial（编辑/内容） | 有节奏的长短句，允许一个判断 | 「先把结构搭对，再谈风格」 | 网络流行语、感叹号 |
| warm（消费/亲和） | 第二人称、口语但克制 | 「这一步很快就好了」 | 「亲」「小可爱」式卖萌 |

一个产品只用一种语气。三套语气混在一页里，比任何视觉问题都更明显。

## 八、占位写法

- 未知内容写 `{{TODO: 需要什么}}`，例如 `{{TODO: 客户 logo，需要 5 个}}`（双花括号成对，里面别再套中文书名号）。
- 交付前 `grep -rn "{{TODO" src/` 必须为空，或每一条都在交付说明里列出来。
- 禁止的占位：`Lorem ipsum`、`这里是标题`、`示例文本`、三段等长的假介绍。

## 九、信息架构三条硬规则

1. **每页一个主动作**，其余降级为次要或 ghost；两个 primary 等于没有 primary。
2. **导航不超过 7 项**，超过就说明产品层级没想清楚（用分组或二级）。
3. **同一信息只在一处出现**；重复出现的指标要能被解释（如顶部汇总 + 表格明细，需明确口径）。

## 十、交付前文案自查

1. 随机挑三段文字，能说出它想让人做什么吗？
2. 有没有出现「赋能/一站式/无缝/极致/重新定义/闭环/助力」？
3. 所有按钮都是动词开头吗？有没有「确定」？
4. 错误提示里有没有告诉用户怎么改？
5. 数字的口径写了吗？单位统一吗？
6. 中英文之间有空格吗？标点是全角吗？
7. 有没有 `{{TODO` 残留？
