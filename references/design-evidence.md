## 一、样本与方法

采集时间 2026-10（A/B 组）、2026-02（Wegic、即时设计）。方法：无头 Chromium 1440×900 打开目标站，等 3–4s（字体与骨架稳定），
读取**实际计算样式**（`getComputedStyle`）：按字符数加权统计字体与颜色、统计字号分布、
取 `h1/h2/p/th/td/label/button/input` 首个实例的字号·行高比·字重、统计圆角与 gap 频次、
量测侧栏/表头/表格行高/控件高度、读取 CSS 变量命名。原始 JSON 未随包分发，重跑即可再生。

**采集成功 28 个站**（A 组 25：16 个营销/产品/电商站 + 9 个内容陈列站，B 组 3 后台），另有 1 个失败不计入。
2026-10-27 新增 4 个中文站（少数派 / 语雀 / 掘金 / 苹果中国）与 2 个认证/电商站（Vercel / 苹果商店），只并入站点计数与单站条目，
**不重算第二节的跨站中位数**——那组数字冻结在原来的 18 个 A 组站基线上，避免历史结论随样本漂移。

## 二、跨站统计（基线：18 个 A 组站——12 营销/产品 + 6 内容陈列；新增 4 站未并入）

- 主题：**浅色 14 / 深色 3 / 黑白交替 1**（Wegic）。浅色仍是企业站默认，深色是差异化选择而非标配；
  黑白交替是产品站的做法（黑段叙事、白段放证据），对后台没有参考价值。
- 正文字号：均值 **14.7px**（10,12,12,13,13,13,14,14,14,14,15,15,16,16,16,18,20,20）；正文行高比均值 **1.42**（1.15–1.60）。
- H1：均值 **69.8px**（36–140，15 站有 h1；UI 世界没有 h1——h2 被拿去装导航；**UI Notes 连语义标题都删了**，最大的字是一个 div；**StyleKit 把 H1 压到 36px**、**Muzli 48px**——目录站不需要向下的海报级主标，页面主角是那些卡），行高比 **0.80–1.51** ——大标题压到小于 1 的行高是普遍做法，但也有 1.5 的（即时设计 40/1.51）；内容站把 h1 压到 **40** 也是常规做法（站酷「UI」频道名 40/1.10）。
- **H1 / 正文 字号比：2.3 – 8.8 倍**（营销站语境；内容站下限一路下探：站酷 40/14 = 2.9、**StyleKit 36/16 = 2.25**——页面主角不是标题时，标题就该退回 2 倍出头；后台绝不能照搬，见第四节）。
- 主字体：Manrope×2、Inter×2、Geist、Outfit、DM Sans、Season Sans、Ivar Text、IBM Plex Mono、Poppins（Muzli）——
  多数是无衬线/几何/新怪诞，**14 站里 11 站自带 webfont**（系统栈只作 fallback）。
  四个反例都是中文站：**即时设计 `document.fonts.size = 0`、UI 世界、站酷、UI Notes（Avenir 系统栈）**——一份 @font-face 都没有，
  中文渲染完全交给 PingFang/微软雅黑。这不是偷懒：中文 webfont 动辄几 MB，工具站与内容站把首屏速度排在品牌字前面，
  **中文站才成立的取舍**，英文站照抄会失去个性。
- **第二字体是等宽（mono）的有 6/12**：Suisse Intl Mono、Geist Mono、IBM Plex Mono、TheGoodMonolith、Berkeley Mono、Fragment Mono（StyleKit）。
  用途统一：编号、标签、元信息、版本号、时间戳。
  另有一派**第二字体用手写/衬线做「批注层」**：Wegic 的 Damion（4 处 eyebrow）、banham 的 Ivar Headline、Muzli 的 Instrument Serif（296 处 Poppins vs 9 处衬线，衬线只当刊头）。
- **三件套分工第一次出现**（StyleKit）：**衬线写标题、无衬线排正文、等宽只做标签与数值**（Playfair Display + Albert Sans + Fragment Mono）。
  它把「第二字体」升级成「三种角色各管一段」——标题靠衬线拿到编辑感，正文靠无衬线保证可读，等宽只出现在 hex、特征词、数字上。
  代价是**中文标题没有任何中文衬线兜底**（落系统宋体），复现时必须自己补 `"Songti SC", "Source Han Serif SC"`。
- 间距频次：16px(7) ≈ 8px(7) > 4px(4) ≈ 12px(4) > 20·6·24(各 2–3)。
  派生值 `6.4px / 7.47px / 11.2px` 出现在两站——说明间距来自**缩放系数**而非手写像素。
  Wegic 是最极端的一站：gap 4px 出现 38 次、16px 16 次、12px 10 次，**基数就是 4**。
  即时设计给出另一种「缩放」：**根字号 13px + em**，于是所有尺寸都变成非整数
  （22.2857 / 30.797 / 44.564），节奏是「大块上下各 130」而不是 4 的倍数。
  **学它的节奏，别学它的小数**——按 13 的倍数落盘会得到一堆没法标注的值。
- 圆角频次：50%(6，用于头像/圆形)→ 2px(4) → 24px(4) → 4px(3) ≈ 9999px(3) ≈ 999px(3) ≈ 50px(3)。
  **双轨制**：小控件 2–8px 方一点，同时存在胶囊 999/9999px 用于标签与 CTA。
  Wegic 给出更干净的分工：**12px(48 次) 单一主力 → 20px 暗卡 → 9999 标签 → 58 大媒体框**。
  即时设计是反例：**七档圆角（7.43 / 8 / 10 / 11.14 / 12 / 13 / 14.86 / 20 / 22.29 / 1000）没有递进关系**，
  同样来自 em 缩放。圆角必须能一眼看出内外层级，否则只剩记忆成本。
  站酷是反面的另一半：六档（4/8/10/12/16/24）**每档都有明确归属**（输入 4、按钮描边 8、主按钮 10、卡 12、胶囊 16、模态 24），
  所以档多不等于乱——**乱的是同一语义用两个值**。它的胶囊也是 16 而不是 999：内容社区要一点硬度，不做气泡感。
  **直角派（StyleKit）是第五种做法**：陈列区一律 `0`（卡片/输入框/chips/统计格/色板条），圆角只留给控件与圆形图标钮（6px / 50%）。
  直角成立的前提是**内容自己够整齐**（固定 4:3 预览 + 固定文本区高度），否则直角会把参差放大成"排版事故"。
  UI Notes 给出第六种：**2 / 4 / 6 / 16 / 20 / 24 六档，随盒子变大**——促销条小钮 2 → 搜索框 4 → 信息胶囊 6 →
  截图槽 16 → 登录胶囊 20（=半高，全圆）→ 应用图标 24（80 的 30%）。没有一档是「随手写的 8px」，也没有一档跳级。
- 容器宽：1440 视口下主内容 **1250–1450px**，正文段落栏宽收在 600–800px。
  Wegic 用标准 `max-w-7xl` = 1280 + 32 水平内边距，是这一档里最省事的写法。
  即时设计 1277（`max-width: 1280` + 卡片贴满），卡片级圆角 22 直接把容器吃掉——适合「卡片即页面」的产品站。
- 图片：`loading="lazy"` 近乎全量（如 165 张里 164 张），不是可选优化。
- 动画数量 0–34，**中位数 1**：动效克制的那几站并不显得低级。
  Wegic 桌面 8 个、移动 0 个——**移动端做减法才是及格线**。
  即时设计只有 3 个 @keyframes（breath / autoScroll / flow），其余全靠 GSAP 滚动编排；
  它的 hero 用「三屏视频轮播」讲设计→原型→开发，**动画承载信息而不是装饰**，这类叙事也不能上后台。
- **阴影用法分两派**：linear 一派「几乎不用阴影，靠边框」（20 边框 / 2 阴影）；
  Wegic 一派「不用边框，靠发丝圈 + 内阴影」（`0 0 1px 1px` 用了 24 次）。两派都好，
  混着用（每张卡又有边框又有阴影）才是廉价感的来源。
  即时设计是第三派：**不用边框，靠「负扩散阴影 + `0 0 0 1px` 发丝环」**
  （`0 16px 16px -16px` 用 28 次），阴影负扩散不外扩，卡片像贴在底板上。
  戏剧性大阴影（`0 50px 100px -20px`）只给浮起来的设备截图，20 处——**两套分职，才敢用大阴影**。
  UI 世界是第四派：**全站只有 1 处阴影**（而且卡片本来就不画壳）。25 张缩略图同屏时，
  加阴影等于让每张图浮起来，噪声翻倍——**图墙（列表里以图为主）最该走这一派**。
  站酷是同派的成熟版：阴影总频次极低，**最高频 `0 8px 32px rgba(0,0,0,.1)` 也只出现 4 次且全是浮层**（下拉/弹窗），
  内容卡片零阴影零边框，靠 4:3 比例 + 等宽列自己成版——**图墙要靠比例而不是盒子来分栏**。
  StyleKit 把这一派推到极致：**整个 chrome 层零阴影**，页面上唯一那条 `6px 6px 0 0 #000` 硬阴影长在 Neo-Brutalist 卡片**内部**——
  它是**展品**，不是展柜。这是"目录站/画廊站"该有的分寸：**陈列区的层次由版式给，不由阴影给**。
  UI Notes 是这一派的极端：**全站 0 阴影 0 边框**，连发丝环都不要——层级只靠底色（`#fff` / `#f8f8f8` / 渐变段）与间距。
  前提是每一格内容都被强制成同一比例（截图槽 240×520、图标 80×80），**比例一的统一能替代盒子的分栏**。
- **网格密度第一次进入统计**，而且两个内容站给出**两种图墙**：
  UI 世界是「密」派——5 列 × 300、`gap: 0`（间距来自卡片 `padding: 12px`）、25 张/页、一屏 15 张；
  站酷是「疏」派——4 列 × 283、列距 **24**、行距 **36**、8 张/屏、靠留白把作品隔开。
  同期后台列表是 24px gutter + 每行 8–10 条。**同一份设计系统可以有两种密度，但同一屏里不能混**——
  这就是「列表页 vs 后台表格」的分界；图墙再密也不能小于 12px 的列间距，否则缩略图会糊成一片。
  **第三派是「活预览墙」**（StyleKit）：3 列 × 373、**gap 32**、容器 1184、首屏 24 张。
  它比两位图片墙更疏，因为每张卡要装下一整幅"迷你界面"——**卡里东西越多，列间距越大**（24 → 32），这是密度的第三条判据。
  **第四派是「无壳溢出裁切」**（UI Notes）：3 列 × 440、列距 28，但每列塞的是一条 **1248 宽**的截图带，
  外层 `overflow: hidden` 只露 **1.8 张**——密度不靠缩图，靠**把内容裁出画框**。
  代价必须补：裁切处要给出口（「+3」或 hover 提示），否则用户不知道后面还有东西。
- **中文内容站的字号下限被拉到 12px**：副行 12/24 在中文里可读性临界，且 UI 世界那一档灰
  `#7f7f7f` 只有 **3.9:1**。站酷同样踩这一脚（`#888` = 3.54:1，`#999` = 2.85:1），
  但它把**正文压在 14px 并让 14px 承担 934 处**，靠压缩字重与层级而不是字号来提密度——这才是内容站的正解。
  结论：内容站要压密度，但**正文级文字不要低于 14px、次级不要浅于 `#6b6b6b`（4.9:1）**。

## 三、可以直接抄的招式（带出处）

1. **等宽字体做「元信息层」**：编号/时间/代码/标签用 mono，正文用无衬线（5/9 站）。
2. **双轨圆角**：控件 4–8px，标签/CTA 用 `9999px` 胶囊（orizon、kindi、emotion、atmospherik）。
3. **间距走 8 基数**：4 / 8 / 12 / 16 / 24 / 32；需要更细时用缩放系数派生，别手写 13px、19px。
4. **一个强调色打天下**：orizon 只用一个绿 #4ac300、emotion 只用一个紫 #9047ff、kindi 一个靛 #3d3dc2，
   其余全是中性灰阶。**两个以上高饱和并列 = 立刻像模板**。
5. **大标题负字距 + 紧行高**：H1 行高比 0.8–1.15，`letter-spacing: -0.02em ~ -0.04em`（kindi、twodo、emotion）。
6. **表格密度固定值**：th 14px/500、td 14px/400、行高 43–53px（shadcn dashboard 实测 53px）。
7. **控件高度固定值**：桌面后台 28–32px（linear 28/32、shadcn 32），移动触控 ≥44px。
8. **侧栏 232px、顶栏 73px**（linear 实测），不要写 250px/64px 这类「随手整数」。
9. **卡片优先用边框**：linear 页面里「有边框」的卡片 20 个、「有阴影」的 2 个。
   阴影只在浮层（dropdown/modal/toast）上出现。
10. **图片一律 lazy**，并给 `width/height` 或 `aspect-ratio` 防塌陷。
11. **令牌命名两派**（都成立，选一派用到底）：
    - 功能语义：`--bg / --surface / --border / --ink / --ink-soft / --ink-faint`（twodo）
    - 角色语义：`--color-text / --color-text-muted / --color-border`（supermodels）
    - 交互三连：`--primary / --primary-active / --primary-rgb`、`--status-danger / --status-danger-active`（emotion）
12. **状态与强调成对出现**：`--color-on-brand` 必须与 `--brand` 成对定义（本仓 `contrast_check.py` 也据此配对比度）。
13. **负扩散阴影替代边框**（即时设计）：`0 16px 16px -16px rgba(23,25,29,.2)` + `0 0 0 1px` 发丝环，
    阴影不外扩、卡片贴住底板；戏剧性大阴影（`0 50px 100px -20px`）**只**给浮起来的设备截图。
14. **输入与提交同容器**（即时设计）：外框 r15 白底 + 内钮 r8 品牌色，`focus-within` 把焦点环画在外框上，
    比两个独立控件更像「一件事」。
15. **颜色编码阶段**（即时设计）：三列流程用三色 pill（薄荷/薰衣草/珊瑚），颜色承载信息就不是装饰；
    第四种颜色出现时必须换编码方式，不是加色。
16. **同色成段**（即时设计）：`#f3f7fb` 连续 2–3 段再换白，交替换色会把页面切成条。
17. **毛玻璃头部无边框无阴影**（即时设计）：`rgba(255,255,255,.94)` + `saturate(2.5) blur(14px)`，88px 高；
    有促销条时头部 `top` 跟着走，促销条可关后要能回 0。
18. **图列表不画卡片壳**（UI 世界）：25 张缩略图同屏，卡片 `background/border/radius/shadow` 全为 none，
    图 + 一行标题 + 两行副行。分组靠图边界——**壳是给「少而重要」的东西的**。
19. **零 gutter + 卡片内边距当间距**（UI 世界）：`grid gap: 0`，卡片 `padding: 12px`，
    视觉间距 24px 但网格没有 gutter；改密度只需改一个 padding 变量。
20. **缩略图强制同比例**（UI 世界 275×190 ≈ 1.45 + `object-fit: cover`）：
    用户上传来源再杂，墙也不会参差；设计稿预览类改 `contain`。
21. **文字 tab 做 8+ 分类筛选**（UI 世界）：16/500、选中只换色、右侧放「共 N 个」，
    比 8 个胶囊省一半视觉噪声。
22. **两级分类用「形状」区分层级**（站酷）：一级 56px 文字 tab + 3px 短下划线，二级 31px 胶囊；
    两排并列时**不靠颜色也不靠字重**，靠高度与轮廓一眼分得出谁是父级。
23. **等宽图版靠比例成版**（站酷）：卡片 283×264 = 图 283×212（4:3）+ 标题 19 + 作者 20，
    三个数字定死，整页行距自然出现 36；**别让标题换行**，换一行整版就歪。
24. **短下划线做选中态**（站酷）：28×3px 圆头短横线压在文字下方 8px，比整条 border-bottom
    更像「手指点在那」，也顺带把 11 个 tab 的间距锁住。
25. **0.8px 发丝是真实存在的档**（站酷）：分隔线、按钮描边、圆图标钮全用 `0.8px`，
    比 1px 细一档、在高 DPI 屏上刚好是 1 物理像素。**但它在小数缩放下会发虚**——用 `1px` + 低对比色更稳。
26. **列表页顶栏要 sticky**（站酷的反面教训）：它没做，长图墙往下滚就丢了分类与排序；
    图墙页的顶栏 + 分类条合并成一个 sticky 块，高 112 以内。

27. **卡片即预览，别截图**（StyleKit）：陈列"一批彼此不同的东西"时，让每件东西用真 CSS 渲染成迷你 DOM，
    放在固定比例（`4:3`）的裁切框里。截图会糊、会过期、会在窄屏失真；活预览永远准。
28. **6px 四段色板条**（StyleKit）：预览正下方一条 `display:flex; height:6px`，四段 `flex:1`，
    语义固定为**背景/前景/强调/辅色**。一行 CSS 给每张卡一个"身份证"，比写 6 行标签有效。
29. **卡片高度公式相同、内容各异**（StyleKit）：预览 `4:3` + 色板 `6px` + 文本区 `180px`，
    三个数字定死，149 张卡自然对齐成版。**整齐来自公式一致，不来自内容一样。**
30. **hover 只做两笔**（StyleKit）：卡片边框转深 + 标题转强调色，无位移无阴影。
    卡内已经有一整幅彩色预览时，任何额外动效都是噪声。
31. **eyebrow 11px / 0.18em**（StyleKit）：中文页头想要"编辑感"最便宜的一招——
    11px 全大写式疏排一过，H1 立刻从"标题"变成"栏目名"。
32. **整行箭头链接**（StyleKit）：白底 + 1px 边 + `padding 16px 20px` + 右端 `→`，三行叠成一列"下一步去哪"。
    成本是"三个功能卡"的十分之一，可读性更高。
33. **三格统计 + `tabular-nums`**（StyleKit）：页头右侧 `dt 10px / 0.16em` + `dd 20px`，
    `border-right` 分格。数字必须 `tabular-nums`，否则刷新时宽度跳动。
34. **筛选逐层降级**（StyleKit）：11 个场景 chips（38 高）、3 个类型 chips（32 高）、1 个标签下拉——
    越细的筛选，控件越小、越靠后。**同一屏里"更细的筛选"必须看起来更轻。**
35. **一页给三种深度的产出**（StyleKit 详情页）：硬性规则 / 设计说明书 / 创意简报三类提示词并列，
    用户要哪层自取，省掉"你到底想让我怎么用"的来回。
36. **数字当标题**（UI Notes）：`477 个应用 180158 张截图` 用 48/500，数字单独上色 `#446bf8`，说明段退到 18/30。
    全站最大的字给「数量」而不是口号——这是「看起来有货」最省力的做法，比形容词有效。
37. **一个正方形尺寸走三处**（UI Notes）：图标墙的图标与 app 图标都是 80×80 / `border-radius: 24px`，
    视觉重量因此完全对齐。全站只定义一个正方形尺寸，是「墙 + 列表 + 详情」共存的省事前提。
38. **双类目信息胶囊右上纵排**（UI Notes）：`v2.5 - 2026.09` + `74 张截图` 两枚 32 高 / r6 / `#f8f8f8` / 13px，
    右对齐、间隔 8、宽度由内容撑开。不用表格也能把「版本 + 数量」放整齐。
39. **数字必须 `tabular-nums`（复用）**：UI Notes 的大数字与计数若不设等宽数字，加载 66 个应用时会左右跳。

40. **衬线只当刊头**（Muzli）：`Instrument Serif` 48/1.0 只出现在 H1、长文 H2(38.4)、区块标题(30)、页脚 logo，
    296 处 Poppins 对应 9 处衬线。中文替身 `"Source Han Serif SC","Songti SC"` 必须自己补，行高给 1.1（别继承 1.0）。
41. **图版靠图片自己的边界分组**（Muzli）：卡片本体 `border:0; box-shadow:none; background:transparent`，
    只给图片 `border-radius:4px` + `0 0 0 1px rgba(0,0,0,.05)` 发丝环——比每张卡套一个框干净，且省一层阴影。
42. **页脚用主色 10% 当底**（Muzli）：`background: rgba(46,84,255,.1)`，不引入第三个颜色，也不让页脚变成「黑底白字」的第二个世界。
43. **渐变当"墙"而不是"块"**（MasterGo）：`header::after { position: fixed; height: 900px; z-index: -1 }` + `linear-gradient(120deg, #6236FF, #32C5FF)`——首屏之后整页都在"色彩里"，正文区始终是白的。代价：iOS 上 `fixed` 背景会抖且吃滚动性能，**只在 `(min-width: 900px)` 里开**。
44. **属性面板的字段语言**（MasterGo 研发模式）：分组标题 12/600/`#8A8F99`（比内容更安静）+ 键值行 12 等宽 + **只有数值上色**（`#7FB1FF`）+ 分组之间只给 1px 线。深色面板不要套白底的卡片与阴影，会碎。
45. **盒子模型图 > 四行 padding**（MasterGo 代码面板）：嵌套矩形 + 四条边各一个 10px 数字，比 `padding: 16px 16px 20px 16px` 直观；配合"每行 hover 出复制钮"，用户才拿得走。

## 五、中文场景补充（无对应获奖样本，按可用性推导，标注为推断）

- 中文正文行高比取 **1.6–1.75**（西文 1.44 不可直接搬：汉字无升降部，1.4 会显挤）。
  即时设计是反面样本：13px / 1.50，字小行紧，靠「卡片多、段落短」掩盖——长文场景会难读。
  站酷把 14px 配 **1.36**，只在「标题 + 一行元信息」的卡片里成立（没有长段落），**有段落就必须回到 1.6**。
- 中文字重只用 **400 / 500 / 700 三档**；600 在多数中文可变字体上缺失，会跳回 700。
- 中文标点与数字混排时数字用 `font-variant-numeric: tabular-nums`（表格金额列对齐）。
- 小程序/H5：正文 15–16px、次级 13px、最小 12px；触控目标 ≥44×44px；`viewport-fit=cover` + 安全区。

### 7.2 五条能直接用的结论

1. **目录页的标题结构是「1 个 h1 + 一片 h3」，不是「h1/h2/h3 递减」。**
   awwwards 1/10/29、muzli 1/3/68、stylekit 1/1/12、zcool 1/27 都符合；
   卡片标题一律 `h3`，`h2` 只留给大分区（或者干脆不用）。
   照抄「每个区块都开 h2、卡里再开 h3」会得到比这些站更碎的目录页。

2. **地标数量与站点质量无关，与「有没有人管无障碍」有关。**
   同一批样本里地标从 **0 个（语雀）到 21 个（Muzli）**，中位数 3–4。
   语雀 0 地标、0 语义标签、36 张图只 1 张带 `alt`；Muzli 21 个地标、216 个链接全是 `<a>`。
   两个站都能用——所以地标是**加分项不是及格线**，但你自己写的时候至少要 `header / nav / main / footer` 四件套。

3. **`img` 的 `alt` 覆盖率两极分化，且和站点类型强相关。**
   图片即内容的站（uinotes 80/80、luckymaomi 143/143、awwwards 60/60、wegic 67/67）全部覆盖；
   结构靠 `div` 堆的站（语雀 1/36、即时设计 81/127、MasterGo 84/178）大面积缺失。
   规律：**当图是唯一信息载体时，`alt` 是刚需；当图只是装饰时，它被跳过。**
   自己写的时候按「这张图删掉，信息是否丢失」判，丢了就必须有 `alt`。

4. **DOM 深度均值 6–20，超过 20 就说明在拿 `div` 当布局胶带。**
   vercel 6.1（413 节点）、uishijie 8.1（1351 节点）、luckymaomi 9.5（3852 节点）都在 10 以内；
   即时设计 19.9 / 最大 30、掘金 18.1 属于偏深。深度不是越浅越好，但**均值破 20 基本等于「每层只包一个 div」**。

5. **`button` 与 `a` 的分工是硬规矩，样本里没人混。**
   applestore 43 button / 105 a（选项用按钮、跳转用链接）、stylekit 46/54、holynova 27/42；
   Muzli 反过来是 **0 button / 216 a**，因为它整页都是跳转。
   判据只有一条：**点了会换 URL 就是 `a`，点了只改当前页状态就是 `button`**。

### 7.3 三条反例（样本自己也没做对）

- **语雀**：0 地标 + 0 语义标签 + 36 张图 1 个 `alt`。全 `div` 结构在视觉上没问题，
  但键盘用户无法跳读，图片在屏幕阅读器里全是「图像」。
- **即时设计**：127 张图 46 张无 `alt`，`aria-*` 只落在 7 个节点上，深度均值 19.9。
  结构层做了（nav / main / contentinfo 齐全），内容层没跟上。
- **UI 世界**：唯一地标是搜索 `form`，`aria-*` 为 0，用 2 个 `h2` 装导航文字、48 个 `<br>` 排版。
  这是「能用但不可维护」的典型：改版时没有任何语义锚点可依。
