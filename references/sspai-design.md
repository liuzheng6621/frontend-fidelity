# 少数派首页：960px 内容板与多形态编辑流

> 采样日期：2026-10-27；对象仅为 <https://sspai.com/> 公共首页，不登录、不全站爬取。
> 视口：桌面 1440×900、移动 390×844；另有 1440×900 首屏、DPR 2 全页截图及 760 / 767 / 768 / 1000 / 1024px 定向复测。
> 读法：尺寸均为当次计算样式或盒模型实测；内容会更新，整页高度不是设计令牌，未复测项明确写「未验证」。

## 一、证据范围与纠偏

- 通用探针覆盖桌面 590 个计量元素、84 张图，移动 463 个、83 张图；另读首屏、双端全页截图与双端审计详情。
- 定向脚本只测首页关键选择器、媒体偏好与少量视口；原始证据为 `sspai*.json`、`audit-sspai.json` 和当次截图。
- 通用探针的 `metric('p')` 命中 banner 的 24px 文本，不是文章正文；本文改用文章标题、社区正文等定向结果。
- 本次未得到可复用的中文长文正文 `p` 样式，因此不把 14px/1.43 写成首页正文令牌。
- 截图与实时量测的页面总长略有变化；以下优先记录容器、比例、间距和重排关系。

## 五、圆角与间距不是同一套基数

- 桌面探针圆角高频为 8px×24、50%×19、4px×12、24px×8、99px×6；没有证据支持「6px 为主」。
- 4px 给标准文章缩略图，8px 给小媒体与合集图，10px 给 34×34 日期牌，12px 给桌面讨论按钮。
- 20 / 24px 分别给移动 / 桌面主 banner；99px 给直播、商城 pill；圆角随组件体量与形态变化。
- 大间距有三档：文章上下 32、Prime 上下 64、Prime 头部下距 40；不要用统一 24px 段距抹平编辑节奏。
- 桌面文章文图 gap 48，移动降到 16；顶部编辑板与移动网格都用 16。
- 左栏与文章列之间由 `.feed__main` 左右 56px 外距形成；这不是卡片内部 padding。
- 移动页边距 16、内容 358；顶栏与主 section 的容器规则要分开实现。

## 六、布局与导航

- 固定 header 高 56，采样中内部容器 1232、左右 padding 16；导航项约 90–106×56，右侧图标按钮 32×32。
- 主 section 在 1440 下为 1024 外宽、960 内容宽；x=240 的内容轴与 x=104 的顶栏轴并不相同。
- 左侧推荐导航桌面宽 164，共 5 项、每项高 56；1000px 时缩为 80，767px 及以下由 64×28 的移动下拉替代。
- 右栏只确认 1024px 仍显示、1000px 已隐藏；不要虚构两者之间的精确断点。
- 1000px 时文章列扩至 832；这说明中间桌面会重分配栏宽，而非始终锁死 520。
- 768px 仍是桌面 board=flex、移动下拉 0×0；767px 切为 board=grid、下拉 64×28、feed gap 16。
- 390px 下无横向溢出，右栏消失、feed 单列，但仍保留长首页与多个编辑模块。

## 七、九个首页模块逐件拆解

### 7.1 顶部编辑板
桌面是 224 / 480 / 224 三列、两个 16 间隙的 960×480 编辑板；不是等宽三列卡片。移动改 grid，主图占满 358，两张小编辑卡各 171。

### 7.2 主轮播 banner
桌面外框 480×480、r24、浅底加 1px 边，无普通投影；移动 358×358、r20。底部文字层用渐变与 blur 保证白字可读，分页与轮播另行处理。

### 7.3 派早报
桌面为 224×224 方卡；34×34、r10 日期牌形成视觉锚点，摘要为 13px/18px/500。移动不是保留左栏，而是把派早报并入主轮播。

### 7.4 次推荐与直播 / 商城
次 banner 桌面外框 224×141、内部 222×139；移动 171×88、内部 169×86。直播 / 商城 pill 桌面 224×78、r99，移动 171×72，形态与方图卡明确区分。

### 7.5 共创与一派
共创桌面 224×224、r24，内部图约 130×95.14、r8、cover；标题 13/500，副题 13/400、`#6f7174`。一派桌面 224×141、r24、padding 20，标题 13/500、描述 11。移动两者改为约 169×174.11 的横向 slide，不能照搬桌面卡结构。

### 7.6 标准文章卡
桌面 520×189，内容体 188、上下 padding 32；文 306×124、图 166×124、gap 48，图 r4。移动 358×161，文 215×96、图 127×96、gap 16；标题由 20/34 降为 17px，不靠缩图解决全部适配。

### 7.7 重点文章卡
桌面先用 520×520 方图建立专题权重，再接高 140、padding 24 的内容区；当次整卡约 725。它是文章流中的「停顿」，不应每条都使用，也不应把 725 写死。

### 7.8 Prime 社区
桌面内容宽 520、上下 padding 64；头部高 65、margin-bottom 40，正文 15/22.5/400。桌面讨论按钮 100×36/r12，移动 78×24/r8，弱灰底而非品牌红实心。

### 7.9 派友在看合集
右栏宽 164、padding-top 32；两项各 164×83，图 162×81、r8，项间 16。它用低宽度、小缩略图承接补充阅读，不与 520 主文章列竞争。

- Matrix 只确认到顶栏链接、文章元信息标签及部分带正确 alt 的 16×16 图标；未验证独立的首页 Matrix 模块。
- 未找到可见的「榜单」或手机「下载」模块标题；只见 `/page/client` 的「少数派 App」链接及客服扫码线索，不能补写成已证实模块。

## 八、组件状态与响应式

- 轮播非激活 slide 的计算样式仍可能显示为 visible，实际由 overflow 裁切；视觉隐藏不等于键盘与读屏已隐藏。
- 文章整卡链接、banner 与内部控件的焦点顺序、可读名称、重复 Tab 停止点均需人工走查；本次未下确定结论。
- CSS 中存在导航 / 按钮 `all .2s`、部分图片 `transform .15s` 等声明，但 hover 定向尝试未得到可靠前后差异。
- 因此 hover、focus-visible、active、disabled 的最终效果均标为未验证；不要凭 transition 声明补写视觉状态。
- 移动推荐下拉为 64×28；菜单、登录、logo 等触控目标有 32×32，头像甚至 16×16，不能直接沿用桌面点击区。
- 390px 已完成单列重排；760px 虽为移动布局，顶部 section 仍约 1125 高、feed 约从 y=1182 开始，主内容出现得过深。
- 对比之下，390px 顶部约 582 高、feed 约从 y=639 开始；中间视口需要单独限制主图或调整模块顺序，而非只验两个端点。

## 九、动效、性能与暗色边界

- 动效证据包括 Swiper 轮播、pagination opacity `.3s`、bullet `.2s`，以及根变量短时长 `.15s`、默认 `.36s`。
- `prefers-reduced-motion` 未验证；复刻时至少应停自动轮播、移除非必要位移，并保留手动切换。
- 桌面 / 移动探针分别见 84 / 83 张 `img`，原生 `loading="lazy"` 均为 0；定向样本另见 13 个自定义 lazy 标记。
- 桌面 / 移动约 66 / 67 个图片 URL 带 WebP 线索，并见 CDN `imageMogr2` 处理痕迹；实际请求、解码与缓存仍须网络面板确认。
- 因而应写「存在定制懒加载与 CDN 处理迹象」，不能笼统写成完全没有懒加载，也不能把 URL 参数当作已优化完成。
- 自动截图采样 CLS 桌面约 0.000374、移动 0，console 与 HTTP error 均为 0；这只是本次加载结果，不是长期性能预算。
- 暗色媒体模拟后正文计算色变为 `rgb(226,226,230)`，但 body 在明暗两次读取中都透明；整页表面、图片、对比度和手动切换均未完整验收。

## 十、性能与可访问性审计怎么读

- 自动审计原始计数为桌面 42 error / 20 warn、移动 32 error / 36 warn；数量不能直接换算成可见缺陷数量。
- `element-overlap` 很多来自轮播：主 banner 可视窗约 x=481–959，下一张从 x=959 起；共创窗口 x=977–1199，非激活 slide 可位于 x=731 等窗外位置。
- 审计只比较非零矩形与 display / visibility，不计算 overflow 裁切、opacity 或真实遮挡；这些 banner / 整卡链接重叠是自动审计信号，不直接判为视觉重叠。
- 仍需键盘与读屏复核非激活 slide、整卡链接和内部链接是否重复聚焦或被重复朗读，不能把「疑似误报」写成「无问题」。
- axe 双端均有 `image-alt=19`、`scrollable-region-focusable=2`、`meta-viewport=1`；本次首页也未测到可见 h1–h4 大纲。
- 可访问名计数为 `button-name` 桌面 6 / 移动 2，`link-name` 桌面 7 / 移动 1；图标按钮需要显式名称。
- viewport 含 `user-scalable=no`、`maximum-scale=1.0`，限制缩放；移动小字和小点击区又进一步放大可操作性问题。

## 十一、可迁移的六种手法

1. **先定内容轴，再定顶栏轴。** 正文用 1024 外框 / 960 内容，顶栏可更宽；不要让 logo 与文章标题被迫共用一条无用轴线。
2. **首屏用非等宽编辑板。** 在 960 内按 `224+16+480+16+224` 分配主次；内容减少时可删侧列，不要把三张卡强行拉成 320。
3. **文章流只给重点内容加壳。** 标准卡无壳、上下 32；重点卡才用方图和内容区。层级来自编辑权重，不来自统一阴影。
4. **文图比随视口重算。** 桌面 306/166、gap48，移动 215/127、gap16；标题同时从 20 调到 17，保持图与标题区的视觉平衡。
5. **侧栏在移动换形态，而非只做 display:none。** 派早报并入主轮播，共创 / 一派变横向 slide；补充右栏则可隐藏。
6. **品牌色只做定位点。** 白、浅灰与黑灰承担大多数界面，红色留给出处、日期或关键状态；不要给每个按钮染红。

## 十二、七处别照抄

1. **别照抄 8 / 9 / 11px 小字。** 新站正文与元信息应另设可读下限，页脚也不能例外。
2. **别照抄 16×16、64×28、32×32 的触控区。** 视觉图标可小，交互热区要扩大并留间距。
3. **别省标题大纲。** 编辑型首页更需要唯一 h1、模块 h2 与文章 h3，而不是全靠 div 的字号表达层级。
4. **别省按钮与链接名称。** 搜索、写作、登录、关闭、轮播前后按钮都应有可访问名。
5. **别禁止页面缩放。** `user-scalable=no` 与 `maximum-scale=1` 不应进入复刻模板。
6. **别把裁切外 slide 直接留给辅助技术。** 自动重叠不等于视觉 bug，但必须复核并正确管理 tabindex、焦点与可读状态。
7. **别只验 390 与 1440。** 760px 的首屏过深说明中间视口会失衡，应增加约 760px 的版式验收。

## 十三、与另外三个内容参考站的差异

| 站点 | 桌面组织 | 视觉重心 | 移动结果 |
| --- | --- | --- | --- |
| 少数派 | 960 内容板 + 三栏 feed，文章主列 520 | 轮播、方图、无壳文章与社区混排 | 767px 真重排；390 无横向溢出 |
| uishijie | 5 列×300、零 gutter | 密版图墙、卡片无壳 | 移动适配弱 |
| zcool | 4 列×283、24px 列距、4:3 图 | 两级分类后的等宽作品网格 | 有横向溢出问题 |
| uinotes | 3 列×440、真实截图陈列、无壳 | 截图即内容，界面退后 | 锁定 1420，整体缩小而非重排 |

- 少数派值得补进参考库的不是另一种图墙，而是「编辑首屏 + 多形态文章流」；它比其他三站更依赖内容角色与模块顺序。
- 若只做作品集网格，应参考 zcool / uishijie；若做中文资讯或社区首页，才优先搬这里的 960 内容轴与 520 文章列。

## 十四、搬用清单

1. 建两套容器：header 按自身宽度，主 section `max-width:1024; padding:32px`，桌面内容保持 960。
2. 先摆 960×480 编辑板，严格使用 224 / 480 / 224 与 16 间隙；移动改 grid，不在桌面 flex 上硬挤。
3. 主 banner 用 1:1、r24（移动 r20）、浅底 1px 边；文字层补渐变、blur20 与 48/24/24 padding。
4. feed 以 520 文章列为中心，桌面左右各留 164 侧栏及 56 间隔；右栏隐藏规则需按自身内容另验。
5. 标准文章卡只画文、图与分隔节奏：上下 32、桌面 gap48 / 移动 16、图 r4，标题 20/34（移动 17）。
6. 按编辑权重少量插入重点方图卡或社区模块；重点卡高度由内容决定，不锁 725。
7. Prime 用 64 段距与 40 头部分隔，讨论按钮沿用弱灰底；不要让所有模块都获得同等视觉重量。
8. 在 767px 切移动布局，390 下保持 16 页边距、358 内容与 `171+16+171` 两列小编辑卡。
9. 额外验收 760 / 768 / 1000 / 1024 四档；760 控制首屏深度，1000–1024 检查右栏与文章扩宽。
10. 上线前补齐标题语义、图片 alt、控件名称、44px 级舒适触控区、页面缩放、轮播焦点管理和 reduced-motion。
11. 用网络面板确认真实图片格式与加载时机，保留 CLS 观测；不要把自定义 lazy 标记或 WebP 参数当作完成验收。
12. 榜单、独立 Matrix 首页模块和手机下载区均为未验证内容；没有自己的产品证据与内容需求，就不要补进复刻稿。
